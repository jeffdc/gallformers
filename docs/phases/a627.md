# Migration through the import

The old site's Facts go in as packages of Gallformers legacy data through the same import path as any paper (plan doc, *The old site's data and the Gallformers notes*; Jeff, 2026-11-15). Only what isn't a Fact is copied directly, each kind through its one writer. Then the migration and the cutover replay are one mechanism: copy the skeleton, apply the base packages, then apply later packages in order.

## What exists

The study `/Users/jeff/dev/gallformers/docs/plans/2026-11-12-history-audit/state/6-migration-via-import.md` (2026-11-12) found:
- The migration already writes every Fact through the import's own writers (`Catalog.assert_fact/4`, `Taxa.assert_act/4`). What it skips is the layer above them: the contract, the validator, the resolver, the comparison with what's held, the queue and the replay log.
- About 95% of the ~65,800 migrated attributions can be said in today's contract. The rest need small contract additions (below).
- Galls and plants keep their old ids by staying in the skeleton: a package can't create a Gall with a given id, but a Gallformers-family package can name an existing Gall by id.
- One big package fails (database parameter and lock limits, a quadratic append). Packages of about 50 Galls work: roughly 175 packages, an estimated 6-10 minutes against about 3 today, unmeasured.
- Every applied package is recorded in the replay log, and the migration never clears it, so base packages would be replayed again at cutover unless they're applied unrecorded.

## What this phase builds

- **A Source form for Gallformers legacy data in the contract** (undated). The 324 range exclusions from the old site's stored ranges are legacy data too (Jeff, 2026-11-15), so no undated Gallformers statement is needed. Plus the two other additions: an alias kind (125 former labels; today an imported alias always becomes a common name) and placements at the root of the tree (91 taxa; today a placement needs a parent).
- **The import fit for bulk use:** batched inserts within the database's limits, no quadratic appends, base packages applied without a replay-log entry, a run inline with the ID tool's index refreshed once at the end, and package files readable in local rehearsals.
- **A package builder** that turns each kind's existing migration plan into packages of about 50 Galls, extending the Gallformers package builder (`GallformersFragment`) rather than copying it, and declaring taxa by accepted name, rank and id.
- **The comparison check**, at two levels: inside one run, every planned statement is looked up and compared field by field, and the Source holds nothing beyond the plan; across two builds of one production copy, a dump keyed by stable references is diffed. It reuses the existing checks (`Taxa.Sync.check`, the production-data invariants, the ID parity tool, the migration tests) and ignores the bookkeeping the import adds on purpose.
- **One kind of Fact at a time**, each behind the comparison check, in the study's order: common-name aliases, Traits, Inducers and Hosts, the non-plant taxonomy, former labels; then plant taxonomy, generation and abundance. Ranges come from the *Ranges* phase.
- **Legacy packages for the new Fact kinds** (Jeff, 2026-11-16): plant taxonomy, a Gall's generation and its abundance. The dropped fields (data complete, lead Source, curator notes) aren't migrated. The range migration is the *Ranges* phase's.
- **A full run measured on a production copy**, with the database-level comparison clean.

**The undescribed-Gall confirmation step** (today 14,334 of those Galls' Facts are also stated by Gallformers, dated the run day, so they don't show unconfirmed) is kept or dropped once the Gallformers notes analysis shows whether processing the undescribed notes as Sources makes sense (Jeff, 2026-11-15). Dropping it would make backlog bug 5248 moot.

**One-time reshapes of the old tables stay** (Jeff, 2026-11-15): the migration's own re-keying of images and key couplets is a conversion step, not a second writer. The old Host range rows aren't re-keyed: the *Ranges* phase replaces them with WCVP Facts. Data the app also writes (WCVP links, generation-group links) goes through its one writer.

What happens to the existing Sources' records and citations (6,679 copied today) comes from the *Existing Sources* phase, which this phase waits for.

## Done when

- The migration writes no Fact directly: every Fact of the old site is in a Gallformers legacy data package applied through the import path.
- Records that aren't Facts are copied through their one writers.
- The comparison check shows the result equals today's direct migration, apart from the agreed bookkeeping.
- The base packages don't appear in the replay log.
- A full run on a production copy is timed and fits the cutover window.

Sources: the study above; Jeff, 2026-11-12 to 11-15 (decision log).
