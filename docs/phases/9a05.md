# Rehearse and cut over

Rehearse the cutover on production copies until it is boring, then cut production over in one maintenance window and merge `taxogall` to `main`.

## Strategy (decided)

- **One cutover in a maintenance window**, rehearsed many times on production copies. There is no long-running dual-write. Scale is small (~10⁶ rows), and the maintenance-mode runbook exists (`runbooks/planned-maintenance.md`).
- **The backscan runs on preview, not in the window.** Curators process and approve Sources on preview, which holds a copy of production. At cutover, preview's replay log is replayed into production after the data migration. The backscan of ~927 Sources takes weeks, so it can't happen inside the window.
- **The replay must cover every decision a curator makes, not only batch files.** That includes:
  - which Gall an ambiguous match maps to;
  - synonyms or plants added in the Host-name step;
  - dispute rulings, Fact and term edits;
  - taxonomy-admin edits, and tree edits as Facts (acceptances, declines, statements credited to a Source);
  - Undo, corrections, deletes and merges.

  Every replay kind must be idempotent: a stopped replay can be re-run after a fix, and Oban retries never apply a change twice.
- **What reaches production:** only the curated files (`priv/catalog_migration/*.csv`) and **preview's** replay log. Curation done on a local database reaches production only if it is redone on preview or, for fixes to v1 data, put in a curated file. That covers review decisions, Host-name synonyms and plants, Trait-term placements and taxonomy edits.
- **Changes on the live site meanwhile:** the data migration always runs from the latest production copy. A short **edit freeze** comes before cutover. Sources new or changed since the backscan get a final small backscan pass.
- **The data migration is not a boot-time Ecto migration.** Schema migrations run automatically at boot (`RUN_MIGRATIONS=true` via `docker-entrypoint.sh`, `Ecto.Migrator` in `lib/gallformers/application.ex`). The catalog migration is long-running, and at boot it would stall under Fly health checks and `HealthWatchdog`, risking restarts mid-migration. It runs as its own explicit step in the window: `Gallformers.Release.migrate_catalog()`, which starts only the repos (WCVP's too) and the S3 client, not the endpoint, Oban or the watchdog.
- **Rollback:** a full pre-cutover backup, a rehearsed restore, and a time limit after which we fix forward instead of rolling back.

## Rehearsal (repeat until boring)

- Run the full migration plus the replay on a fresh production copy (`make experiment-db` locally), then on the Fly preview environment for production-like timing.
- **Time the migration** to size the maintenance window.
- **Rehearse rollback:** restore the pre-cutover backup and confirm the old release runs against it.
- **The verification suite:**
  - counts reconcile (Galls, Hosts, Sources, images, Gallformers codes);
  - every old `/gall/:id`, `/host/:id`, Gallformers code and image path still resolves;
  - `/taxonomy/:id` (through the crosswalk) and the non-gall redirects work;
  - old ID-tool bookmark URLs resolve to the same filters. `fa` holds an old taxonomy ID, and old family IDs overlap plant IDs, so an old link must not quietly resolve to a plant. `co`, `sh`, `fo`, `se` and the like hold trait-vocabulary IDs. `ng` shows non-galls, which aren't migrated;
  - the four keys resolve;
  - ID tool and search parity on a sample of real queries: `mix gallformers.catalog.id_parity` compares the old query with the new one on the converted copy. There are two expected differences. The potential range now includes Hosts' introduced range. And every Gall's range is now its Hosts' whole WCVP range, since stored ranges become no Facts apart from the 34 range-confirmed Galls;
  - API responses are compatible;
  - the tree follows the taxonomic Facts: `Gallformers.Release.check_taxa_sync/0`;
  - a hand spot-check of a set of well-known Galls.
- **One-off settles** on a database migrated before the code that needs them, which applies to preview:
  - `Gallformers.Release.recompute_contests()` once. Migration `20261107140000_add_fact_contests` gave existing name and synonymy Facts their contests without recomputing standings, so synonymies that a revalidated name should supersede change only at their next write until it runs.
  - `Gallformers.Release.backfill_wcvp_authorship()` if the database was migrated before plants took WCVP's authorship, or WCVP was unreadable during the migration.
- **Carry-over of phase 1 taxonomy decisions** runs as part of `Release.replay_log/1`, after the replay (`Gallformers.Import.TaxonomyCarryOver`). Phase 1 tree-changing synonym decisions, and acts a curator followed, become acceptances of the Source's statements. Unmatched ones are reported for a curator. Splits are never auto-accepted.

## Release gates

- **Storage:** before production, verify that:
  - the private bucket blocks public access;
  - the application's credentials can read, write, list and delete privately;
  - incomplete multipart uploads expire after seven days;
  - only approved public outputs reach the public bucket.
- **Public database snapshot** (`.github/workflows/db-snapshot.yml`, `priv/snapshot/tables.txt`): it must exclude the new private tables (stored Source text, import packages, disputes, the admin queue, the replay log, change sets). `test/gallformers/public_snapshot_test.exs` fails while a table is unlisted.
- **Old code kept only for the cutover goes at cutover:** `Gallformers.Galls.Identification` (`lib/gallformers/galls/identification.ex`) and `mix gallformers.catalog.id_parity` exist only for the ID-parity check.

## Cutover (in order)

1. Announce the window. Start the edit freeze.
2. Final small backscan pass for Sources added or changed since the backscan, and approve them.
3. On preview, export the replay log to the private bucket with `bin/gallformers eval "Gallformers.Release.export_replay_log()"`, and keep the key it prints. No preview decisions are made after this.
4. Take a full production backup to S3 and verify that it restores.
5. Enable maintenance mode (`runbooks/planned-maintenance.md`).
6. Deploy the release. Schema migrations run automatically at boot.
7. Run the data migration as a separate step, not at boot: `bin/gallformers eval "Gallformers.Release.migrate_catalog()"`. It is strict: it stops with nothing written on any pending curated decision or duplicate taxon key. Then replay preview's log with `Gallformers.Release.replay_log("<key from step 3>")`. It stops on the first entry it can't replay, names that entry, and can be re-run after a fix.
8. Run the verification suite against production.
9. Smoke-test as a curator and as a visitor. Lift maintenance mode.
10. Watch errors, Oban queues and traffic, and apply the rollback criteria.
11. Merge `taxogall` to `main`.

## Done when

- The rehearsal on preview runs the whole sequence with no surprises, with a measured time and a rehearsed rollback.
- Production runs on the new back-end, with the verification suite passing against it.
- The cutover-only code is deleted, and `taxogall` is merged to `main`.
