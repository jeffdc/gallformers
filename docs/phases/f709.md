# Preview environment

Give preview (`gallformers-preview`, gallformers-preview.fly.dev) what steps 5 and 6 need:
- its own Postgres holding WCVP and a production copy converted by the catalog migration;
- a `fly.preview.toml`, a `Dockerfile.preview` and a runbook that describe preview as it now is.

## What preview is for

Preview is no longer a disposable deploy. It is **the persistent staging server for the backscan and the cutover:**
- **Step 5:** Sources are processed into a copy of production on preview, by Jeff and Adam. All of the Gallformers notes are processed there before the public release too (`20e5`). Several curators will review there (`6611`).
- **The backscan runs on staging, and curators' approvals are recorded there** (`b5bd` M0). The ~927 Sources take weeks and can't happen inside a maintenance window. Curators also decide things outside the batches: which Gall an ambiguous match is, synonyms or plants added in the Host-name step, dispute rulings, taxonomy edits, new Trait values and term mappings. **Everything that changes data on preview is written to its `replay_log`.** The log is ordered and keyed by stable keys: batch IDs and statement refs, taxon names, legacy IDs, never database IDs (`9449` §5).
- **At cutover, preview's replay log is the only carrier of those decisions to production** (with the curated files). M6:
  - step 3: on preview, `bin/gallformers eval "Gallformers.Release.export_replay_log()"` writes `replay/replay_log-<UTC time>.json` to the private bucket; keep the key it prints. No preview decisions after this.
  - step 7: on production, `Gallformers.Release.migrate_catalog()` (strict), then `Gallformers.Release.replay_log("<key>")`. The replay stops at the first entry it can't replay and can be re-run after a fix.
- **Step 6, rehearsal** (`b5bd` M5): run the full migration plus replay on a fresh production copy (`make experiment-db`), "then on the Fly preview environment for production-like timing", to size the maintenance window.

So preview's database must survive deploys and outlive the backscan, and it must not be destroyed or restored over while it holds decisions not yet exported.

## Design and constraints

- **Its own Fly Postgres app** (`runbooks/postgres-cutover.md` names it `gallformers-preview-db`). Since the March 2026 Postgres cutover, preview has had no database: it had shared `gallformers-db`, which became production's.
- **Two databases on that cluster:** the main one, and `wcvp`. `config/runtime.exs` derives `Gallformers.Repo.WCVP`'s URL from `DATABASE_URL` by replacing the database name with `wcvp`. WCVP is loaded by pg_restore from the S3 dump artifact (`runbooks/wcvp.md`); it is not managed by Ecto.
- **The data:** a production copy (the latest full backup in `gallformers-full-backups`), converted on preview by `Release.migrate_catalog()`. That copy holds private tables such as `users`. Putting it on Fly is sending personal data to a service other than Anthropic, which needs Jeff's OK first.
- **Migrations:** schema migrations run at boot (`docker-entrypoint-preview.sh` runs `Release.migrate()`). The catalog data migration never runs at boot: it is long-running, and Fly health checks and `HealthWatchdog` would restart the machine mid-run. It runs as its own step on the machine (`b5bd` M0). It is strict: any pending curated decision or duplicate taxon key stops it with nothing written. Its rebuild never truncates `replay_log` (`9449` Task 17).
- **Storage:**
  - The private bucket `gallformers-private` is shared by preview and production on purpose (`Gallformers.Import.ReplayExport`). Packages live under `import/<key>/`; the migration never deletes them, nor Sources or their stored documents; the exported log goes under `replay/`.
  - Images go to the images bucket under the `preview/` prefix (`S3_IMAGE_PREFIX`).
  - Tiles come from production's CloudFront (`TILES_URL`).
- **Production-like:** the VM matches production's (shared, 1 CPU, 1 GB), so timings carry over.
- **Secrets the app reads** (`runtime.exs`): `DATABASE_URL`, `SECRET_KEY_BASE`, `AUTH0_DOMAIN`, `AUTH0_CLIENT_ID`, `AUTH0_CLIENT_SECRET`, `S3_PUT_AWS_ACCESS_KEY_ID`, `S3_PUT_AWS_SECRET_ACCESS_KEY`, and `TILES_URL` unless it is set in the toml. `gallformers-preview.fly.dev` is already allowed in `check_origin`.

## Not settled in the matters

Raise these with Jeff as the work reaches them:
- How preview's database is backed up while it holds unexported decisions.
- Whether, and when, preview's production copy is refreshed before curators start. After they start, a refresh loses their work unless the log is exported and replayed.
- How M5's "on preview, for production-like timing" rehearsal fits with preview holding the backscan. A full migration on preview's own database would rebuild what curators made there.

## Done when

- gallformers-preview.fly.dev runs the taxogall code on its own Postgres, with WCVP loaded and a production copy converted by a clean strict `Release.migrate_catalog()`.
- `fly.preview.toml` and `Dockerfile.preview` describe what they do now (no "disposable", "baked-in database" or "WCVP sqlite"), and differ from the production files only where preview really differs.
- One runbook covers what preview is for, setting it up, its secrets, loading WCVP and the production copy, running the catalog migration on it, and exporting its replay log. Someone can follow it without reading the matters.
