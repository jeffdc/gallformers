# Edit model: back end

Build the back end of the unified edit model Jeff set on 2026-11-07: one path for every Fact edit, and one Gallformers Source whose changes are packages. The UI side (one editor framework, the Fact inspector on taxon, rank and Source pages, the full audit) is the next phase, "Edit model: one editor".

## Terms

- **Source:** anywhere Facts are derived from.
- **Gallformers Source:** Gallformers' own statements of Fact, usually backed by an Observation. Append-only: each change dated when made, and by whom.
- **Gallformers ID Notes:** editorial prose, nothing to do with Facts.
- **Gallformers legacy data:** everything from the old site, before any Source is ingested. Undated.
- **Change:** one package of the Gallformers Source (a curator's edits, applied from the tray).
- **Reading:** how Gallformers read a Source, the Facts it took the Source to state with its words as written. A misreading is fixed under the Source's authority, at its date, with no Gallformers position. Not a **Correction**, which the domain model defines as a Source's published erratum (a newer Source). ("Reading" is in `docs/domain/domain-model.md`.)

## The rules

1. **Any Source may state any Fact.** The literature is the usual authority; Gallformers may state any Fact, taxonomic included, as an exception. (This settles the swing between "Gallformers is the authority" and "only the literature": the middle.)
2. **New Facts come in exactly two ways:** ingest a Source to approval, or edit/add a Fact on a Fact-bearing entity.
3. **An edit is the ingestion of a Gallformers statement,** resolving to the same changes through the exact same code path as a Source ingestion. No second code path creates Facts.
4. **Sources never reference each other formally.** A curator may write "Weld (1959)" in a statement's text; it stays text. Source-Source relationships are latent, via shared Facts only.
5. **Galls and Gallformers' non-plant taxonomy are Fact-bearing, with the same mechanics** front and back. Host-Gall is a Gall Fact; plant records are editorial.
6. All edits that can be inline are inline on the main pages, with one shared set of components, mechanics, validators and code, so a bug in editing is fixed once (the next phase's UI).
7. **Correcting an ingestion mistake:** the corrected Fact overrides the incorrect one with the original Source's authority; the change is audited (who, why, when). It is the same act as review, with lower ceremony.
8. **Delete** is only for data added by mistake: a true exception outside the rules.
9. **Split and lump are taxonomic acts, so Facts,** under the authority of the Source whose statement decides them.

Review edits are under the Source's authority: edits during review correct import errors or map what the original couldn't be read for, so every review action states Facts *from the Source*, not from Gallformers or the curator (who is in the audit). Review decisions that change the non-plant tree become that Source's statements in its package.

## The structure: a change is a package, not a Source

The Source is the authority; a package is one arrival of its statements. There is one Gallformers Source (one search result, one Source page). A change is a package of it: small, timestamped, audited (who). The old site's data is its undated base, so the literature outranks it and the backscan can correct it. Each old ID note processed is a change with the note's date.

The attribution is the Source's current position on a Fact: a newer package from the same Source replaces its earlier statement (a Source's newer word supersedes its own); recency between Sources is unchanged. History lives in the packages (batch files and `batch_statements` per Fact), so "what Gallformers said about this Fact over time" and "what this change did" are queries; the Gallformers Source page lists its changes.

The same model covers every Source: a first ingestion, a corrected re-ingestion, an author's update, review corrections and Gallformers changes are all packages of a Source through one code path. The one Gallformers-specific rule: its statements take their change's timestamp, not a single authored date.

Accepted trade-off: earlier Gallformers positions on a Fact are history one click away, not separate voices.

Rejected, with reasons: a Source record per change (thousands of tiny Sources would swamp search and Source views without condensing code); one Source with several statements per Fact (a wide change); replace-only with history only in the audit.

## The tray

One tray, items grouped by authority (Jeff: required whichever entry point). An ordinary edit is a Gallformers change; a fix of a Source's reading is under that Source's authority. Applying makes one package per group (one Gallformers change, one package per Source whose reading was fixed), all through the one ingestion path. Notes on a Fact and the editorial fields are an Editorial group, applied to the record at once, not as a package.

## What this phase builds

- The legacy-data Source merges into the Gallformers Source as its undated base. "Legacy-only" becomes "only Gallformers' undated base", still shown as unconfirmed.
- Statement dates become timestamps. Standing between Sources still compares at day precision; Gallformers' own same-day changes never compete: the later replaces.
- Restating a Fact carries the earlier statement's evidence forward (today a new Gallformers statement on the same Fact replaces the earlier one and wipes a note-derived statement's quote).
- ID notes leave the Gallformers Source (today Source 58 also holds them) as editorial records on the Gall.
- History views read from packages: the Gallformers Source page's changes, a Fact's Gallformers history.
- `attributions.cites_as_written` / `cited_source_id` removed (stored, never read; they break rule 4).
- Every taxonomic edit through packages: the taxonomy admin's and species page's "Based on which Source?" (`BasisPicker`), which writes a curator's statement in a paper's name at the paper's date while the tray credits the same act to Gallformers at today's date (two models of one act), is retired; curator edits are Gallformers changes, misreadings are reading fixes, and no curator edit is credited to a paper. Synonym decisions in review (`SynonymDecisions.carry_out`, which changes the non-plant tree with no statement, drifting from `Taxa.Sync`) become the reviewed Source's statements.
- The other direct Fact writes go through packages: Source corrections, merge and rename aliases, split answers, vocabulary term moves and term placements outside apply.
- The name/authorship comparison is one rule on every path (today the taxonomy admin compares raw strings and the review queue normalises, so "(Weld 1959)" vs "(Weld, 1959)" makes a new name statement).
- Replay gaps closed: Gall editorial tray edits, name-part edits and note saves are audited but not replay-logged, a cutover risk.
