# Import at scale

Make the import fast and cheap enough for many Sources, before they are processed into a copy of production in bulk (the "Process Sources on preview" phase needs this one). Two halves: the Gallformers side (the dry run and each review decision must stay quick on a large Source) and the producer side (cost per Source, the reference answers it is scored against, and where it runs).

## Speed: the dry run and decisions

**The problem.** `Import.preview_package/2` is the dry run behind the review's reading of a Source and its Facts list: it applies every pending batch in an audited transaction that is rolled back, and it is recomputed after every decision. A decision also re-resolves the package's names. At 49 Galls (Nastasi & Davis 2022, package 97) the dry run took 0.25–1 s; a Source of ~570 Galls (Gagné 1989) would wait on it after every decision.

**Measured** (2026-11-08, on a copy of `gallformers_taxogall`):

| Package | Dry run before | Dry run after the slot fix | A decision (re-resolve) |
|---|---|---|---|
| 118, 21 Galls, gall batch writes ~200 Facts | 1.8 s | 0.7 s | 0.34 s (resolve) |
| 116, 39 Galls, gall batch held | 1.2 s | 0.9 s | 0.65 s |

- **The slot fix** (now the baseline): `Facts.with_slot_siblings/1` used `id IN … OR slot IN (subquery)`, a full scan of `facts` on every Fact written (2.5 ms × 362 per dry run). Reading the slots first and passing them as a list lets both conditions use their index. It also speeds up approval.
- **Still linear:** the dry run costs ~3.5 ms per Fact written (~25 small queries per Fact: attributions, evidence, names, Carbonite transaction rows, locks). A decision costs ~16 ms per Gall to re-resolve the package (taxon name, common name and ancestry lookups per name). For ~570 Galls that is roughly a 15–20 s dry run in the background and a ~9 s wait on every decision.

**Two routes:**

- **(A) Batch** the per-Fact and per-name queries in the Fact writer and the resolver. General; it also speeds up approval (which runs the same apply); maybe 3–5×.
- **(B) Recompute only the Galls a decision touches:** re-resolve and re-preview just those. Riskier: a taxon or Trait-term decision touches many Galls, and a partial recompute must match a full one.

**Decided (Jeff, 2026-11-08): route A first.** Measure it on a large test package; only then decide whether B is needed at all.

**The test package:** the five trial Sources of the v6 run combined (`services/import-producer/output/v6-2026-11-07/`, local: Osten Sacken 1862 corrections, Floate 2010, Nastasi & Davis 2022, Aphis rubifolii, Ashmead 1896). Build it repeatably so the same package is measured before and after.

**How to profile:** one dry run and one decision on that package, on `gallformers_c90c` (127.0.0.1:54317, a fully migrated copy of `gallformers_taxogall` kept for this; drop it when the phase is done, asking Jeff first). Count queries per table with a telemetry handler on the Repo's query events (`[:gallformers, :repo, :query]`); time with `:tprof` (it needs `Mix.ensure_application!(:tools)` first).

**What to batch:** the largest classes in the profile. From the 2026-11-08 counts: Carbonite transaction inserts (~534 per dry run), locks, per-Fact attribution and evidence inserts, Source lookups (~163), `trait_term_mappings` lookups, and the resolver's per-name lookups. As of a0434bcf, the apply is each batch's runner (`Gallformers.Import.ApplyGall` for gall batches) inside `Audit.transaction`, collected by `Gallformers.Import.Preview`; names go through `Gallformers.Import.Resolver` and `Taxa.resolve_name/2`. Batching must not change what the dry run or approval writes, or what the audit and replay log record.

**Callers.** As of a0434bcf the review's own dry run (`ReviewLive.Review`) and the Facts page's (`ReviewLive.Facts`) both call `Import.preview_package/2` once per package; the review cleanup (b230 Task 5) replaces the first with the second, which merges several packages and handles errors. The function being made faster is the same either way.

## Cost

About $9–14 a paper (about $2.50 for a single web page), API-equivalent, billed to Jeff's Claude subscription (the producer, `services/import-producer`, runs headless Claude Code and strips `ANTHROPIC_API_KEY` from the child process so runs bill the subscription). Opus 5.5 produces (phases 2–3) and responds (phase 6); Opus and Sonnet both review (phase 5). From the trial, per phase: phase 2 about $0.50–1.20; phase 3 $1–5 (scales with the Source); phase 5 about $0.75–2.60 for both reviewers; phase 6 about $0.50–1.70. The five golden Sources cost $41.67 on 2026-10-27 (computed by the same script that later proved to skip the checkers, so possibly low; unverified), $45.85 in the format 4 re-run (v4, 2026-11-02; first reported as $32.44, which left out phase 5), $44.85 in v5 (2026-11-03) and $48.70 in v6 (2026-11-07). The producer's README still says $3–10 a Source.

The levers to settle before scaling:

- **One checker instead of two:** about −22%.
- **A cheaper model for checking and responding.**

Constraints on both: the golden regression set is run again whenever the guide, the prompts, the vocabulary or the model changes, so a lever is judged by its golden score as well as its cost. In format 4 the checker places every Trait term blind, and a new term is placed for every Source automatically when the producer and the checker agree on it independently; anything else goes to a curator. A weaker or single checker therefore changes what curators are asked, not only what the run costs.

## Reference answers in format 4

The reference answers are to be rebuilt in format 4 from reviewed packages. Today the golden regression set (`services/import-producer/golden/`) holds Jeff's verdicts from the five trial check pages: 177 statements and 18 name matches, taken from format 3 packages. `produce golden score <run-dir>` matches each item in a new run by meaning (Galls by their identifying fields, statements by a natural key per kind) and reports it present, changed or missing; it already reads format 4 Trait statements (`term` and `category`). Who specifies the rebuild, and when it becomes work, is an open question.

## The producer's shape (item 274b)

- **Stages that write once.** A run lives at `sources/<source id>/runs/<run id>/` in the private bucket, one folder per stage: taxonomy, galls, check-opus and check-sonnet (independent of each other), respond (skipped with no findings), ready. Each LLM stage writes its files, its prompt and transcript, and a `result.json` last (status, engine and exact model, turns, time, tokens, cost); a stage is done when its `result.json` exists, and a failed attempt is overwritten (the bucket's versioning keeps the old one). Phase 4 becomes each LLM stage's closing validator check.
- **`run.json`** is written once when the run starts and fixes the conversion, the contract, the vocabulary and each stage's engine, model and effort, and names the curator. A new run may reuse an earlier run's stages by reference. Starting a run is what shows a Source as being read, so there is no separate claim.
- **A swappable engine.** `claude-code` first; non-Claude and local models allowed, each earning a stage by passing the golden set for it. The engine reports the model it ran (today the producer stamps `producer.model` itself: backlog bug). The Claude-specific parts (flags, the `Bash(...)` allowlist, the stream-json result, tool names in the prompts) move into its adapter. A first trial of Inkling 2 Mini is in `services/import-producer/output/inkling-2026-11-21/LEARNINGS.md` (local).
- **Against preview.** The producer signs in with a personal API token, fetches the contract, vocabulary and prompts the server publishes (prompts move to `priv/import/`), uploads each stage through signed URLs, and asks preview to register the run's package in place (Preview environment phase).

## The producer at scale

The 2026-11-12 history audit found producer problems no record tracked:
- **Long Sources were never tried.** Catalogues and keys of 150 to 350 pages (Gagné 2008, Felt 1917) were converted but never produced, and the whole text goes into one prompt. The largest Sources are this kind.
- **A garbled conversion goes unnoticed.** Felt 1917 "succeeded" garbled; conversion quality is measured and nothing acts on it.
- **Completeness and reliability at 1,000+ Sources** is Jeff's main worry (2026-11-05), and nothing measured it: the v5 run's possible regressions against the reference answers rose from 12 to 19 and were put down to run-to-run variation without a check.
- **The producer guide is drifting back** to the "Never/Don't" style Jeff rejected on 2026-10-11, and six v6 disputes show the producer not following its own guide.
- **The package checks are written twice,** in Python (`priv/import/validate.py`) and Elixir (`Import.Validator`), by hand, with known differences.
- **The golden scorer reads the old tables** for name matches, so it breaks at cutover.
- **Each Source's cost** is in its run logs but nothing adds it up or keeps it with the package.
- **How a curator produces a package and gets it in, and where the producer runs,** are now designed (item 274b, above). Websites with many pages take one document per cited page (7a50 decision c00f), collected by URL in *Collecting Source documents*.

## What the existing Sources' fates need (Jeff, 2026-11-16; decisions on item 7a50)

*Process Sources on preview* lists which Sources are processed and how. The producer needs these for it; the numbers are from the brief (item 6936, https://claude.ai/code/artifact/678cca11-6e01-4849-9dec-3a102100093d):

- **Section-by-section reading of long Sources.** 2,956 of the old per-Gall links open the Source's own BHL or HathiTrust scan at the page where that Gall's entry starts: they are the sections, already drawn up per Gall. Gagné 2026 (Source 897, 467 born-digital pages) is the first long Source. The brief lists the others (Felt 1917, Felt 1940, Weld 1926, 1957 and 1959, Kinsey 1923 and 1930, Gagné 2008, two Zootaxa monographs, the World Catalog).
- **Excerpts as a document**, for a Source no copy can be got for: each Gall's excerpt is one item, bracketed insertions are stripped (2,181 excerpts have them: headings like `[Phenology]` and curator commentary), and the package says it is a transcription. Russo 2021 may need this if no PDF comes.
- **Fetching documents automatically:** BHL (PDF and OCR per item; its API needs a free key), HathiTrust (check what a non-member can download for Weld 1957 and 1960 and Felt 1940), the AMNH and Smithsonian repositories, and open publishers.
- **A lookup pass** over the 128 Sources whose link isn't the document, finding a real copy and fixing the link, checked by a curator.
- **One document per cited web page** for website Sources (209 pages over 20 Sources), each read and dated on the day it's read.

The brief's estimate, from the trial's costs: about $8,700 API-equivalent and 245 hours of runs before the long Sources. Curator review time and the subscription's rate limits are unmeasured (questions on item 6936).
