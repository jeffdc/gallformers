# Migration data

Settle the data the catalog migration gets wrong before the cutover. The problems are in the v1 data itself, or in how the migration reads it: plants that are really genera, plants kept twice, synonyms naming a different plant, and old Gall names that don't reach the new model. Nothing here changes the migration's design. It adds or corrects curated decisions, and extends the migration only where a decision can't be expressed yet.

## The constraint: what reaches the cutover

The cutover runs the catalog migration on the latest production copy (`b5bd` M0: "the data migration always runs from the latest production copy"). Then it replays preview's log (M6 steps 3 and 7). **Only two things reach production: the curated files and preview's replay log.** Curation done on a local database, such as `gallformers_taxogall` (review decisions, Host-name synonyms and plants, Trait-term placements, taxonomy edits), reaches production only if it is redone on preview, or, for a fix to v1 data, put in a curated file.

So:
- **A fix to v1 data goes in a curated file** in `priv/catalog_migration/`, or (rarely) is made on production's own v1 rows before the cutover copy is taken.
- **A fix to something a review created** (a taxon added by a decision) is made on preview, where it is logged for replay. Or it is fixed in code, if the replay itself must behave differently.

## The mechanism: curated decisions

`Gallformers.CatalogMigration.Curated` reads the CSV decision files in `priv/catalog_migration/`: `non_galls.csv`, `range_decisions.csv`, `aliases.csv`, `keys.csv`, `taxon_merges.csv`, `plant_merges.csv`, `kingdoms.csv`, `added_taxa.csv`, `placements.csv`, `generation_group_taxa.csv`, plus `name_suffixes.csv`. Columns are found by header, so a worksheet the migration writes (`--reports DIR`) can be saved as a decision file. Each row's note says who decided and when.

The migration's cutover mode is strict (`Gallformers.Release.migrate_catalog/0`; locally `mix gallformers.catalog.migrate` without `--skip-pending`): any pending curated decision or duplicate taxon key stops it with nothing written. A decision that can't apply is itself pending.

The files used here:
- **`aliases.csv`** (`owner, owner_id, alias_id, name, type, decision, target, note`; `Gallformers.CatalogMigration.Aliases`). It sorts every old alias by meaning, not by field: `synonym` (of the owner's taxon, or of `target`), `common_name`, `former_label`, `code` (Galls only, never a taxon name) or `drop`.
  - Former labels and codes must never be taxon synonyms: synonyms feed import name resolution and would cause silent wrong matches.
  - Synonyms are stored without a trailing generation tag or author citation.
  - Gall common names become `alias_facts` of kind `common_name` mechanically; plant scientific aliases are plant synonyms (rule 4).
  - As of a0434bcf there is no sensu column.
- **`plant_merges.csv`** (`species_id, into_species_id, note`; `Gallformers.CatalogMigration.PlantMerges`, step 11c). It runs the editorial plant merge (`Gallformers.Import.Merge`) once Facts, names, notes and images are written, and logs nothing for replay:
  - the absorbed plant's names become synonyms of the plant kept;
  - its Host Facts, notes and images move to the plant kept;
  - its ID redirects to the plant kept, and it is deleted.

  Both sides must be plant `species` rows. Shipped rows (Jeff, 2026-11-08, per WCVP): 4863 into 4878 (*Silphium asteriscus* var. *dentatum* into *S. dentatum*) and 5190 into 4870 (*Horkelia congesta* into *Potentilla congesta*).
- **Genus placeholders.** A v1 plant row with `genus_placeholder = true` ("*Quercus* spp.") becomes no taxon. It stands for its genus: a `:genus_placeholder` crosswalk entry redirects its old `/host/:id`, its `host_range` rows move to the genus, and Galls on it are hosted on the genus. As of a0434bcf no curated file can mark a row as a placeholder.

**WCVP is the reference** for what is one plant and at what rank (the local `wcvp` database, `wcvp_names.taxon_rank`, `taxon_status`). For plants, Gallformers is editorial: WCVP eases input, and curators may differ from it. Where WCVP's answer is surprising (*Populus trichocarpa* sunk into *P. tristis*), check other authorities before following it.

**Tests.** Add a case as old-style seed rows in `priv/repo/test_seeds.sql`, with its curated decision in `test/support/fixtures/catalog_migration/`. `make test-db` converts the seeds with the real migration. Test first.

## The data

**One-word plant "species".** Seven v1 plants are one-word species under a same-named genus, linked to WCVP Genus records: Justicia 6135, Myrceugenia 6246, Bersama 6509, Tiliacora 6517, Neoboutonia 6521, Malacantha 6527, Echinops 7019. The fix (`b5bd`): mark the old rows `genus_placeholder`, or add curated decisions, so the migration makes them the genus. The query that finds them, and any like them: accepted plant names at species rank or below with no space, or equal to their parent's name; then check each linked `wcvp_id`'s `taxon_rank`.

**The bogus *Stephanomeria*.** It is a review creation, not v1 data. A Host decision on the Nastasi & Davis Source added WCVP's genus record 3134307 as a species of that name under a new genus, because the rank was guessed from the name. Fixed in code (`8fa64e12`: the rank comes from WCVP's `taxon_rank`; logs made with the old bug replay to the genus). What's left is folding it on whatever copy holds it (preview, `gallformers_taxogall`), and running the same query there for others.

**Plants kept twice, and misapplied synonyms** (matter 8861). The catalog migration turns aliases into synonyms, and the resolver picks the accepted name without saying so. Two kinds of problem follow:
1. **One plant kept twice:** a Source naming either plant links to only one row, and the Galls on the other go unmatched.
2. **A synonym naming a different plant:** a Source using the name in its misapplied sense resolves to the wrong plant.

Found by looking, after a rebuild, for a plant name accepted on one taxon and a synonym with no sensu on another, then checking each against WCVP.
- WCVP says one plant (merge candidates): *Cupressus nootkatensis* 2160 / *Callitropsis nootkatensis* 1271; *Cupressus pigmaea* 2236 / *Hesperocyparis pygmaea* 1268; *Fallopia japonica* 4728 / *Reynoutria japonica* 1529; *Grindelia robusta* 3384 / *G. hirsutula* 3181; *Alnus viridis* 36 / *A. alnobetula* 5308 (a species against WCVP's subspecies); *Populus trichocarpa* 4539 / *P. tristis* 249 (needs an outside check).
- WCVP says two plants (the synonym needs a sensu, or should go): *Quercus dumosa* / *Q. cornelius-mulleri*; *Q. texana* / *Q. buckleyi*; *Berberis dictyota* / *B. aquifolium*; *Solidago stricta* / *S. virgata*; "Ulmus pumila Walter" on *U. alata*; *Aristolochia durior* on *Bignonia capreolata*; "Quercus parvula (shrevei)" on *Q. parvula* var. *shrevei*.
- The second source of error: normalizing alias text throws away an author or a qualifier, so a distinct name becomes another plant's name.

What isn't known: how many more there are. The scan misses:
- the same plant under two names where neither name is on the other row;
- an infraspecific row duplicating its species with no alias;
- a misspelling with no alias.

Also unknown: whether the duplicates came from ingesting the Nastasi guide (Jeff's belief, unchecked) or from earlier entry, and which sense the Sources citing a misapplied name meant (*Quercus dumosa*, 64 Galls, matters most).

Jeff decides each pair and name (two open questions on this plan). Merges go in `plant_merges.csv`, and sensu or drop decisions in `aliases.csv`.

**Lost Gall aliases.** Jeff (2026-11-05): the Gall page's "Also known as" must include **all** of a Gall's old names, common names included. Compare the old aliases (`alias` / `alias_species`: 2,196 scientific and 283 common on Galls) with what the new Gall page reads: the Inducer's non-accepted `taxon_names`, plus the Gall's `alias_facts` of kind `former_label` and `code`. 224 old scientific aliases appear nowhere (209 on described Galls, 15 on undescribed). Some are formatting (a generation tag dropped); some are really lost (misapplied names with an authority, common names filed as scientific); some were dropped by rule-2 decisions made before Jeff's 2026-11-05 call. Each gets a meaning in `aliases.csv`.

## Done when

On a fresh production copy, a strict catalog migration runs clean (nothing pending, no duplicate taxon keys), and on its result:
- the one-word-plant query returns nothing, and none of the seven old IDs is a species;
- every plant pair and misapplied name Jeff has decided is applied through the curated files;
- every old Gall alias appears on its Gall page as a synonym, former label or common name, except those Jeff has agreed to drop.

Review-created mistakes like *Stephanomeria* are folded on preview, and a test shows that replaying the log creates no such species.
