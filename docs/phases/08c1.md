# The UI: full accounting, built on stubs

## Why

Jeff judges the plan's completeness by using the screens, not by reading the plan (Jeff, 2026-11-14). So the UI is accounted for and built first, against the back-end interfaces, stubbed where they don't exist yet. The *One write path* phase then fills those interfaces in, and *One editor* connects the finished screens.

## Rules

- **One screen per kind of data**, plus the import, both calling the same code (plan doc, *One write path*). The accounting flags every place two screens edit the same data.
- **The design system** (`docs/design-system/`): reuse its components; propose a catalog entry before building anything it lacks.
- **Stubs are marked as stubs**, so nothing reads as working that isn't.

## What the accounting covers

Every screen that exists, public and admin, against what Gallformers needs. What it needs comes from the domain doc, the plan doc and the decision log, including:
- everything a Gallformers curator can do under the Gallformers Source (a Gall's Inducer, generation and descriptions, creating a Gall);
- the range screens (the *Ranges* phase; open questions in item 7128): the ID tool's place picker, which takes non-leaf places, and the first-visit Region prompt; why each Gall matched, on the ID tool and place pages; the Gall map's predicted and observed layers, and the Host map; stating *only within* and *absent from*, adding occurrences (from iNat and the literature), and the conflicts queue;
- the editorial decisions of 2026-11-16: the dropped fields' screens removed (the data-complete chip, lead Source, Fact notes), and the Gallformers code shown only on undescribed Galls;
- Gall relationships beyond Host and Inducer;
- uploading a Source package;
- the taxonomy, renames and merges queues, reachable at all times;
- the old notes' editorial ID Notes field.

The plan doc's design items feed in wherever they show up as screens (Jeff, 2026-11-15): ranges (the ID tool and range curation), exactly which data is editorial, how a curator produces and loads a package, and the unified approach to editing.

Also inputs to the accounting (2026-11-12 history audit):
- the photo attribution rule (images refuse a save without full attribution; the old site only warned; Jeff was asked three times and never answered);
- calls agents made on the editing screens that nobody confirmed (notes in the tray's Editorial group, the name qualifier's species-only plant search, a separate photo tray item, no Gall search on /admin/observation, reading-fix Trait values skipping term placement, a withdrawn Fact keeping Confirm…);
- look changes six agents made on 2026-11-06 that Jeff never reviewed (photo manager copy controls, Host-range select-all, the country drill-down's hatching, the discard wording, Source chips);
- accepted but never built: the plant picker's "Not here? Add the plant first" link, the tray's "left a while" reminder, "Adam has unapplied changes here" beyond the Gall page;
- the Gall page's Inducer section taking too much room (backlog 5f22).

Two design items come before any building: **one unified approach to editing**, starting from *One editor*'s inspector decisions, and **what can be undone** (today only review answers; not tray changes, taxonomy edits, deletes or merges).

Each screen is marked missing, partial, duplicated or fine. The 2026-11-12 state report on editing (`docs/plans/2026-11-12-history-audit/state/2-editing.md`) lists today's seven editing surfaces and is the starting point.

Building items are added after Jeff has reviewed the accounting, since which screens need building isn't known before it.
