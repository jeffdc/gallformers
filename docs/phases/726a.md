## The rules that apply here

**Docs agents read must describe the code that exists.** a856 deleted the old-domain admin and the modules behind it:
- `Galls` (except `Galls.Identification` and `Galls.Summary`), `Plants`, `Species`, `Taxonomy` and `FilterFields`;
- the species-keyed `Ranges`, `Images` and `Sources` functions;
- the old Gall, Host, gall–host, range and Source screens.

`CODING_STANDARDS.md` and `docs/architecture/` still describe them as if they were current: `Taxonomy` name ownership, the `SpeciesNameOwnership` Credo check, the `Species`/`Taxonomy` associations, the species-keyed range tables, and a SQLite/Litestream C4 model. A doc that can't be made accurate should say less, not stay wrong. The domain docs, CLAUDE.md and the runbooks are replaced after release, in the "After release" phase; this phase covers only `CODING_STANDARDS.md` and `docs/architecture/`.

**Replacing a component follows the design system** (`docs/design-system/README.md`):
- Start from its inventory, in `docs/design-system/inventory/`.
- Keep every listed behaviour, unless Jeff approves a change and it is recorded under the inventory's "Approved changes".
- Prefer new markup around unchanged logic.
- Delete the old one in the same change.

For typeaheads, Jeff (2026-11-05): "Typeahead behavior must not change. Look and feel may improve, but the exact mechanics are hard-won and must be reused or replicated." The catalog's `typeahead` is the approved consolidation of `typeahead`, `multi_select`, `multi_select_dropdown` and `multi_select_typeahead`: one component for single and multiple selection. `multi_select_dropdown` is the last of the legacy components bc0d's handoff named as still in use.

**Production fixes go through main first.** 2c8c's rule: each production bug gets its own small fix branch off main (Jeff pushes and opens the PR), and the same fix goes onto taxogall when it applies there.
- So taxogall periodically takes main in. Where taxogall already rebuilt the code, as with the role-checked live sessions (#596) and the content image upload events (#597), taxogall's side wins in a conflict, and nothing taxogall deleted comes back.
- Workflows that run from main (the database snapshot) change on main and are carried into taxogall at the next merge.
- Never push main. A merge commit passes the review gate.

**Dead references go.** A dropped table, route or component leaves no name behind in code that still runs. For example, `Import.Undo`'s `@machinery` list still names the dropped `vocab_requests` table. But records kept on purpose stay, like the `vocab_requests_decided` replay kind, which keeps old replay-log entries readable.

**CI must check what `make ci` checks.**
- The gap: dialyzer had dropped out of GitHub CI by accident in January (the only workflow running it was deleted as legacy). 13 dialyzer errors then landed unseen.
- The fix: c800 added a Dialyzer job to `.github/workflows/ci.yml`. It is unverified until it runs on GitHub.
- The catch: `ci.yml` runs only on pushes to main, pull requests into main, and manual dispatch. How taxogall gets a run is an open question for Jeff. c800 closes after one green dialyzer run on GitHub.
