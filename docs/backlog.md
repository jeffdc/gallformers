## Bugs

From the [2026-11-26 architecture review](architecture/reviews.md#2026-11-26-baseline) (Jeff: all of them go here). Locations are at `taxogall` bd3c5061.

- **A manual Deploy run on any branch deploys it to production.** `deploy.yml`'s `workflow_dispatch` has no branch guard, so running it on `taxogall` would put the new back-end on production before cutover. Guard it to `main`.
- **A deploy run can poison the CI cache** (Jeff, 2026-11-26; CodeQL `actions/cache-poisoning/direct-cache`, rated high, raised on oaks' copy of the workflow). `deploy.yml`'s smoke test uses `actions/cache`, which also saves the cache, after checking out the ref the run started on, so a manual run from another branch can write `deps` and `_build` entries that later CI and deploy runs restore and compile. Restore only (`actions/cache/restore`), as oaks did in its PR #26, alongside the `main` guard above.
- **Read-only mode doesn't stop curators' writes.** `EnforceReadOnly` blocks only the `:admin` and `:superadmin` pipelines' HTTP requests. Public Edit mode (`/gall/:id?edit` and the other pages), the tray's apply (`tray_live.ex:157-164`) and admin sockets already connected keep writing. On `main` too.
- **The content admins write unaudited and are gated only by plugs.** Glossary, articles and keys (`glossary_live/form.ex:33-37`, `key_live/form.ex:32-38`, `article_live/form.ex:148-150`) write with no actor, their tables aren't tracked by Carbonite, and their screens and `/admin/profile` sit in the plug-only scope with no on_mount guard; `UsersLive` doesn't re-check its role in its handler (`users_live.ex:26`).
- **The API rate limiter can be bypassed** by setting `x-forwarded-for`: `rate_limiter.ex:33-50` keys on its first entry, ignoring the client IP the endpoint already took from `fly-client-ip`. On `main` too.
- **Dev uploads go to the production images bucket.** Dev doesn't set `s3_enabled: false`, so with `S3_PUT_*` keys in the environment, image uploads land in `gallformers-images-us-east-1` with no prefix.
- **Image variants are lost on a restart.** `Gallformers.Async.run/1` is an unsupervised `Task.start`; variant generation (`images.ex:209`, `content_images.ex:167`, `storage/images.ex:231`) sleeps 5s for the CDN and then resizes, and a deploy or crash in between leaves an image without variants. The iNat photo import (`inat_import_component.ex:305,330`) and key PDFs (`key_live/form.ex:63`) run the same way. AGENTS.md says durable work runs on Oban.
- **The CSP is report-only and collects nothing, and production has none.** `main` sends no Content-Security-Policy at all, and Sobelow's high-confidence `Config.CSP` finding is what keeps the Security Audit failing (Jeff, 2026-11-26: fixed here, not by ignoring the check; Sobelow only recognises a CSP passed to `put_secure_browser_headers`). On `taxogall` it is report-only, with no report endpoint, so nothing shows what enforcing it would break; iNat photo hosts are missing from `img-src`, six inline `on*=` handlers would be blocked (`core_components.ex:56`, `admin/images_component.ex:267,407,643,696`, `taxonomy_live/range_editor.ex:588`), and there is no test of it.
- **Three `String.to_atom` calls without an allowlist**: `admin/powo_diff_review.ex:450,451`, `catalog_migration/old.ex:14`. Check whether their input can come from a client.
- **`review_components.ex:821` puts unescaped text into `raw/1`.** Today's callers pass literals.
- **Missing production secrets fail silently.** `config/runtime.exs` raises only for `DATABASE_URL` and `SECRET_KEY_BASE`; a deploy without the Auth0 or S3 keys boots and passes the health check and smoke tests, and `PHX_HOST` defaults to `example.com`.
- **The health check's 503 body includes `inspect(reason)`** (`health_controller.ex:16`), which can expose database error detail publicly.
- **Preview may fail browser uploads.** The images bucket's CORS (`infra/s3.tf`) omits `gallformers-preview.fly.dev`, while `check_origin` allows it. Inferred, not tested.
- **Carbonite rollbacks may be refused.** About twenty migrations call `Carbonite.Migrations.insert_migration_transaction/1` with no `meta:` (mostly in `down/0`, e.g. `20261027130000_add_gall_rename_queue_kind.exs:42`); Carbonite's default meta has no actor or operation, so the `transactions_meta_attribution` CHECK would likely reject those rollbacks. Not run to confirm.
- **Checks and settings to change at release.** `db-snapshot.yml`'s sanity check needs 5,000 rows in `species`, which goes after release; `mix smoke_test` checks `/api/v2`, which answers 410 at release; Dependabot's `target-branch: taxogall` and `taxogall` in the `pull_request` branches of `ci.yml` and `security.yml` (#617) go once `taxogall` is merged. For the cutover phase.

- **Contexts reach into each other's tables** (rules S1 and S4; Jeff, 2026-11-26: fix through the owners' APIs). Carbonite's tables read outside Audit; Import querying Taxa, Catalog, Places and Sources schemas; Search, Images and Ranges reading other contexts' tables; Catalog reading Taxa's, Images', Places' and Sources' tables. rules.md lists every location. Pick each up in the taxogall phase that reworks the module (the one-write-path phase rewrites most of Import).
- **Tests hard-code seed IDs and skip the data checks** (rules T3 and T6; Jeff, 2026-11-26). Look seed rows up (`Taxa.get_by_legacy_id/2`) in the 62 routes that hard-code them, turn `TestsOwnTheirData` back on in the 35 files that disable it, and register `FlashOnlyAssertions` once its candidates pass.
- **Production can scale past one machine** (rule O9). `fly.toml` sets no maximum; cap it at one.

- **Upgrade LiveView to 1.2, Hammer to 7, LiveDashboard to 0.9, Boundary to 0.12 and Credo to 1.7.19 on `taxogall`** (Jeff, 2026-11-26: closed on `main` as #615, done on `taxogall` instead). Hammer 7 rewrites its API (`plugs/rate_limiter.ex` calls the removed `Hammer.check_rate/3`); LiveView 1.2 is stricter about component attributes (`target` on `action_button`) and its formatter reformats `gall_live.ex`; Boundary 0.12 enforces the context rules (rules S2, S11), so check it reports the same. Dependabot will open these against `taxogall` once #617 merges.

## Ideas

- **Move onto heartwood, the code shared with Oak Compendium** (Jeff, 2026-11-26; decided in oaks' `docs/facts-expansion/architecture-groundwork.md`, section 3, and `docs/architecture/decisions.md`). A third repo, `heartwood`, holds two Mix packages that gallformers and oaks both depend on as git dependencies pinned by tag (with `sparse:`): `heartwood_guardrails` (`only: [:dev, :test], runtime: false`: the ratchet framework from `GallformersWeb.DesignSystem.Conformance`, `Guardrails.DuplicateCode`, `Guardrails.Retirements`, the pre-commit and pre-push hooks, the reuse review's packet and record scripts, the superset `check-toolchain`, and their tests) and `heartwood_ui` (the photo viewer, then the fragment-and-reader). Pick it up once oaks has tagged both: the guardrails first, then the photo viewer (oaks' fork, with rail paging, backdrop close and a configurable event). For gallformers:
  - Depend on `heartwood_guardrails`. Keep gallformers' own rules, globs and hints in its conformance module, its baselines in `test/support/`, the `duplicates` config in `.credo.exs`, `test/support/retirements.exs`, the commit gate's prose paths and the gallformers checklist in `dev/guardrails/reviewer.md`; the framework, scripts and their tests come from heartwood. The hooks in `dev/githooks/` become thin scripts that run heartwood's and fail closed when `deps/` is missing. CI runs `check-toolchain` after `mix deps.get`. Deletes: the framework half of `conformance.ex`, `test/support/guardrails/`, `Mix.Tasks.Gallformers.Guardrails.Baseline`, `scripts/check-toolchain`, the hook and review scripts' bodies, and the guardrail tests that move to heartwood.
  - Depend on `heartwood_ui` and replace gallformers' photo viewer with heartwood's `Heartwood.UI.PhotoViewer.photo_viewer/1`, released in heartwood v0.2.0 (to come). The final "Upgrade:" steps will be in `heartwood_ui`'s `CHANGELOG.md` for that tag; check this entry against them before starting.
    - Prerequisites: LiveView 1.1.34 → 1.2, because the component's hook and CSS are LiveView 1.2 colocated assets, extracted to `_build/$MIX_ENV/phoenix-colocated/heartwood_ui/`. Tailwind 4.1.12 → 4.2.3 or later (oaks went to 4.3.5 in its PR #36), in `flake.nix`, the `Dockerfile` and `config :tailwind`. Add `NODE_PATH` to the tailwind profile's `env`: `[Path.expand("../deps", __DIR__), Mix.Project.build_path()]`. esbuild's `NODE_PATH` must include `Mix.Project.build_path()` too.
    - Depend on `heartwood_ui` as a git dependency on `jeffdc/heartwood` with `sparse: "ui"`, pinned to the tag, with a `HEARTWOOD_PATH` `path:` override (the same helper as for `heartwood_guardrails`).
    - In `app.js`, `import {hooks as heartwoodHooks} from "phoenix-colocated/heartwood_ui"` and spread it into the hooks. In `app.css`, `@import "phoenix-colocated/heartwood_ui/colocated.css";`.
    - A gallformers wrapper over `photo_viewer/1`. It maps images to photo maps with atom keys: `src`, `thumb`, and optional `full`, `caption`, `creator`, `license`, `licenselink`, `sourcelink`, `source_label`, `attribution`, `uploader`, `lastchangedby`, `reserved`. It uses the `:actions` slot for the admin links: "Add images" when there are no photos, "Edit photos" when there are. It passes `labels` only where gallformers' wording differs.
    - A `.gf-` adapter block maps the `--gf-*` tokens onto the component's `--pv-*` custom properties, which gives it dark mode and density.
    - Update the `photo_viewer` entry in `docs/design-system/components.md`.
    - Deletes: `photo_viewer/1` in `domain_components.ex`, `assets/js/hooks/photo_viewer.js`, its test and its CSS, and the no-op `gallery_index_changed` handlers in `gall_live.ex`, `host_live.ex` and `source_live.ex` (`on_change` is optional).
    - What users will see change: there are no arrows on the stage; moving is by filmstrip, keys and swipe, "n / N" sits on the photo's upper right, and the filmstrip runs directly under the photo. The stage is sized by an aspect ratio rather than a fixed 320px height. The full view gets pan and zoom. The no-photos view is a standard one shared with oaks.
  - Heartwood changes reach gallformers as tags with a `CHANGELOG.md` entry whose "Upgrade:" steps say what to do, and as entries in this backlog. `mix heartwood.status` (in `done-checks`, for information only) shows the pinned tag against the latest. Fixes go to heartwood, never to `deps/`.
