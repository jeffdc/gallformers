Context (phase 2, f923): a non-plant taxon's common names are taxonomic statements (taxon_common_name), counting only once accepted. A paper that agrees with the tree raises no question and stays awaiting.

Chosen: the first common name a Source gives for a non-plant taxon that has none is treated as differing from the tree, so it raises a taxonomy question (accept or decline).

Why (the build notes state the rule without a reason; this is what the code shows): phase 1's rule took a first common name as agreeing ('new information'). Under phase 2 an agreeing statement stays awaiting and never counts, so the common name would never be shown. Raising a question lets a curator accept it. Plants keep phase 1's rule (their data is editorial).

Alternative: accept a Source's first common name for a taxon automatically, as the names and placements of taxa an import creates are (fewer questions; common names are low-risk).

Code: Import.TaxonomyQueue.difference/4 (option first_common_name: :agrees, passed for plants by Import.ApplyTaxonomy), Import.TaxonomyQueue.
