cb28 open question 14. The situation: the client `Gallformers.INaturalist.Taxa` calls `search/1` (`/v1/taxa/autocomplete`, with `matched_term`; an iNat link or number is read as that taxon) and `fetch/1` (`/v1/taxa/:id?all_names=true`: ancestors, children, names, `is_active`, `current_synonymous_taxon_ids`), through Req with the existing retry and test stub. The design said: a generic app User-Agent, never a person's contact details, well under iNat's limits (a handful of requests per import). It didn't fix when the review's search asks iNat.

What was built: the review's "Another plant…" / "Another taxon…" search asks iNaturalist once per search (debounced, 3 characters or more, as WCVP is searched), beside WCVP; the panel asks once for the taxon. Requests go through `INaturalist.get_json/2` with the existing User-Agent "Gallformers/1.0 (gallformers.org)", no person's details.

The alternative: cb28 names none; the evident ones are searching iNat only on request (a button) or caching results.

Why the conservative choice: cb28 gives one reason for all its open questions: where the plan was silent, the conservative choice was taken, and each is easy to change. The 3-character threshold follows WCVP's search, as cb28 says.
