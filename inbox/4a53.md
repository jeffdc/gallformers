Context (ec2c, Jeff's live-use findings 2026-11-06, item 12: the admin dashboard and recent changes didn't update after applying). The fix: the dashboard (Admin.DashboardLive) and /admin/changes (Admin.ChangesLive) subscribe to Audit.ChangeLog and reload on {:change_log, :changed}.

Chosen: the notice is sent when a curator's (:user actor's) audited transaction commits (Gallformers.Audit, outermost transaction only), and after each step the import job takes a package (Curation.PackageListener: an import applied, held or approved). System work doesn't send it, because the change log leaves system work out: the catalog migration and release tasks, mix tasks, and the import's own system-actor writes within a step. So those don't refresh an open dashboard live; a reload shows them.

Note: the decision's wording says 'imports … don't refresh'. As of a0434bcf the import job does refresh after each package step; what doesn't is system-actor work inside it.

Why: the change log lists curators' changes. Broadcasting system writes would refresh pages for changes they don't list, and a migration or bulk task would flood them.

Alternative: broadcast every audited commit, system actors included.

Code: Gallformers.Audit (tell/2), Audit.ChangeLog.changed/0, Curation.PackageListener, DashboardLive, ChangesLive.
