Where it came up: Nastasi & Davis 2022 (package 97 then, 115 now), the Cinquefoil bud gall's texture, "fleshy". The producer mapped "fleshy" to the existing texture value succulent, through an existing term mapping (fleshy → texture: succulent). A checker disagreed by the rule "texture is the surface", so the review asks it as a Trait dispute ("The producer mapped “fleshy” to succulent. A checker disagreed: …").

The conflict: the checker's rule matches our own words. The vocabulary describes texture as "The Gall's surface.", PRODUCER_GUIDE.md says "`texture` describes the surface", and VERIFY_GUIDE.md's example checker summary reads "'Fleshy' describes the tissue inside, not the surface, so it isn't a texture term". But our texture value succulent is defined "The walls of the gall (when fresh) are juicy if cut.", an interior property, and the walls Trait is "What the Gall shows when cut open." (its values: false chamber, mycelium lining, ostiole, radiating-fibers, slit, spongy, thick, thin).

Options:
- Texture is surface-only, and succulent moves under walls. The guides and checkers are then consistent. Changes: the value moves from texture to walls in the vocabulary (owned by the database since 6611 Task 1; traits.json is generated from it by mix gallformers.import.vocab), the fleshy term mapping points at walls: succulent, and Facts already recorded as texture: succulent would need moving (how many: not checked). 6611 records Catalog functions to add a value and add a term mapping, not to move a value between Traits.
- Texture isn't surface-only, and succulent stays. Then texture's description and the guides' "texture describes the surface" rule need rewording, or checkers will keep disputing succulent.

6611 records no recommendation.
