Background. The place counts on /places and /place/:code first included Hosts' introduced ranges, as decided on 2026-10-25 (matter b5bd). So Europe showed 1,577 Galls; with native Host ranges only it would be about 468 (Oceania 707 vs 88, Asia 1,161 vs 516).

Jeff, 2026-11-05: "if a plant is introduced AND the gall is shown to be in the country then it should count".

Later that day he ruled the counts "wildly inaccurate", saying they can't ship: a Gall counts where its Hosts are native, or where a Host is introduced and the Gall itself is recorded in that country; "if the data is not present … the count is 0".

What was built on that ruling (in code as of a0434bcf):
- Known places: PotentialRange.known_for_galls/1, stored in gall_index.known_place_ids (migration 20261105120000), counted by Catalog.place_gall_counts/0.
- An Identify filter, :known_place_codes, which the place page lists through ("Galls known here").
- The evidence used: a current recorded-occurrence Fact (Current.occurrences/1) in the country or one of its subdivisions. A record in a subdivision shows its country; a continent-level record shows none. Galls with no range data are known nowhere.
- Real counts: NA 3,486, Asia 516, Europe 467, Central America 421, Africa 405, South America 336, Caribbean 279, Oceania 88.
- Only 4 recorded-occurrence Facts existed (for one Gall), so introduced regions almost never count yet.

So for the place counts and lists, both halves of the question look answered by that ruling. What is still open is the scope:
- The ID tool's region filter (Identify :place_codes) still uses the potential range (gall_index.place_ids): native and introduced Host ranges, plus Galls with no range data in every region (g.everywhere). It has the same inaccuracy, and it can disagree with the place pages. For example, a North American oak gall whose only Host, red oak, is planted in Europe shows for Europe in the ID tool but not on the Europe place page.
- The Gall maps show the potential range, framed on the native range.

The options:
(a) Only the place counts and lists use known places, as built. The ID tool and maps keep the potential range, and the two disagree.
(b) The ID tool's region filter also uses known places. Galls with no range data, and introduced-only regions without a record, drop out of region searches.
(c) The potential range itself drops introduced ranges, or requires a record for them. That revisits the b5bd 2026-10-25 decision and 8567 rule 10, and changes the maps.

Jeff pinned the wider rethink of how the ID tool handles regions (including Galls with no range data and showing uncertainty) as an idea for after the design work: the captured idea "ID tool: rethink how it handles regions".
