Context (phase 2, f923 Task 9 'Phase 1 decisions carry over'): at cutover, a phase 1 'the Source is right: change the tree' decision counts as that Source's taxonomic statements accepted, so it doesn't come back as a question.

Chosen: the carry-over (Import.TaxonomyCarryOver, run by Release.replay_log/1 after the replay) records these acceptances dated at cutover with no curator (accepted_by_user_id null).

Why: the replay log doesn't keep who made a decision (replay_log rows hold kind, key and payload only), so there is no curator to record; inventing one would be wrong.

Alternative: record the deciding user in replay entries (a payload change for every kind) so the carry-over can name the curator, or attribute the acceptances to a named system actor.

Consequence: the taxon page and the review Facts page show these acceptances with no 'who'. Unmatched decisions are reported for a curator; splits are never auto-accepted.

Code: Import.TaxonomyCarryOver, Import.TaxonomicDecisions, Release.replay_log/1, Import.ReplayEntry.
