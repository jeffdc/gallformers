Context (phase 2, f923, Jeff 2026-11-06, option b): a paper revalidating a name usually states only the name and its placement, not 'N is not a synonym of X'. Rule chosen: once a name is a taxon's accepted name by a dated, accepted statement, an older statement making that name a synonym of another taxon (legacy undated included) stops counting. A curator who disagrees declines the paper. Rejected (a): relying on curators to record the denial each time.

The agent's reading, for Jeff to confirm: the outranking holds even after a later rename of that taxon, i.e. 'once accepted' read as 'from then on'.

The alternative: the old synonymy is outranked only while N is the taxon's current name, so a later rename lets the old synonymy count again. The agent said this is a one-line change.

Code: name and synonymy Facts of one name share a contest on the Fact; Facts.Standing.settle_contests/2 supersedes the older synonymy; declined or retracted, the synonymy counts again. Migration 20261107140000_add_fact_contests added contests to existing Facts without recomputing standings: run Release.recompute_contests() (mix gallformers.facts.recompute_contests) once on a database migrated before it, i.e. preview, before release.
