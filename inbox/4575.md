Context (phase 2, f923): a Source's taxonomic statement (placement, accepted name, synonymy, rank, split, common name) competes by the Source's date, but counts only once a curator accepts it; until then it is recorded and 'awaiting'. Statements of the Gallformers Sources (Gallformers' own and the undated 'Gallformers legacy data', which holds today's tree at cutover) need no acceptance. A question is raised only for a statement newer than every counting statement in its slot. 
Chosen: when an import creates a taxon (a taxon the Source presents as new to Gallformers), that Source's name and placement statements for it are accepted at once, as created; no taxonomy question is raised for them.

Why (from the build notes and the code): a created taxon has no other statement to compete with. Left awaiting, its name and placement would count for nothing, the Fact would be 'unsupported', and the tree (rewritten from counting statements by Taxa.Sync) would disagree with the taxon the import just made; before this rule the drift check (Taxa.Sync.check/0, mix gallformers.taxa.check_sync) listed every taxon an import created as a difference. The curator already approved the Source that brings the taxon in.

Alternative: raise an acceptance question for each created taxon, like any other taxonomic statement (more questions, but every non-legacy taxonomic position would carry an explicit curator acceptance).

Code: Import.ApplyTaxonomy (statements written when the taxonomy batch applies), Import.TaxonomyQueue, Facts.accept/3; acceptance columns on attributions (accepted_at, accepted_by_user_id).
