Background: file_drop (FormComponents, built in 836fbe65 from the image managers' hand-built drop boxes) renders a div[data-dropzone] with a hidden file input. The upload hooks (assets/js/hooks/image_upload.js for ImageUpload, and ContentImageUpload) attach click, dragover, dragleave and drop handlers to it, and the click opens the hidden input. The div has no tabindex or role and there is no key handler, so a keyboard user can't reach it or open the file picker. This was true of the hand-built boxes before it.

The fix: make the drop zone focusable and operable, either as a button (role='button', tabindex='0', with Enter and Space opening the input in both hooks) or with a visible or label-linked file input. Either way both upload hooks change (image_upload.js and content_image_upload.js, which attach the same handlers), as do their tests (image_upload.test.js, content_image_upload.test.js) and the file_drop catalog entry in docs/design-system/components.md.

Options:
- approve the fix now: an accessibility fix for both uploaders that use it: the image manager for Galls and taxa (Admin.ImagesComponent) and the content image manager (Admin.ContentImageManager);
- defer it: today it is mouse and drag only.

The 2026-11-06/07 build left it for Jeff's approval because it changes the upload hooks.
