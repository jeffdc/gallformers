Background (matter 8861; b5bd 'Plants kept twice (2026-11-08)'). In each case one plant holds a name as an alias or synonym, while another plant holds the same name as its own accepted name. WCVP says they are two different plants: the synonym is a misapplied name, or a homonym whose author was lost. In v1 each row was its own species, so there was no conflict. The catalog migration made every plant scientific alias a synonym with no sensu (`aliases.csv`, rule 4, Jeff 2026-10-26), and the resolver then prefers the accepted name without saying so. A Source using the name in its accepted sense resolves to the right plant. A Source using it in the misapplied sense resolves to the wrong one, and the synonym stays on a plant it doesn't belong to.

The seven (Galls hosted in parentheses; the alias row is in `priv/catalog_migration/aliases.csv`):
1. Quercus dumosa 797 (64 Galls); the name is also a synonym on Q. cornelius-mulleri 800 (18). Alias row plant,800,9974.
2. Quercus texana 1055 (3); also a synonym on Q. buckleyi 351 (40). Alias 1160.
3. Berberis dictyota 6985 (1); also a synonym on B. aquifolium 697 (1). Alias 11513.
4. Solidago stricta 3696 (0); also a synonym on S. virgata 4648 (0). Alias 9588.
5. Ulmus pumila 2733 (2); the alias "Ulmus pumila Walter" is on U. alata 495 (4). This is a homonym: U. pumila Walter is an old name for winged elm, not Siberian elm. Normalizing the name drops the author, the only thing that tells the two apart. Alias 8243.
6. Aristolochia durior 1775 (0); also a synonym on Bignonia capreolata 5135 (0). WCVP's A. durior Hill is a Bignonia name, while the plant meant here is probably Dutchman's pipe (Aristolochia macrophylla). Alias 10893.
7. Quercus parvula 338 (5); the alias "Quercus parvula (shrevei)" is on Q. parvula var. shrevei 2701 (4). Normalizing the name drops the part in parentheses, so the alias names the species instead of the variety. Alias 12410.

Cases 5 and 7 show a second source of error: normalizing alias text throws away an author or a qualifier, so a name that was distinct becomes the same as another plant's name.

The options, per name:
- Give the synonym a sensu. A synonym with a sensu is skipped by `Gallformers.Taxa.resolve_name/2` unless the Source names that sensu ("without it, misapplied names are skipped"). Plain uses of the name then reach the plant that holds it as accepted, and the misapplied usage stays recorded on the plant it was used for. As of a0434bcf, `aliases.csv` has no sensu column, so doing this in the migration means extending the alias decisions (`Taxa.add_synonym/4` already takes `:sensu`).
- Remove the synonym: change its `aliases.csv` row to `drop`. The name then resolves only to the plant holding it as accepted, and the record of the misapplied usage is lost.
- Leave it: the silent wrong match stays.

What isn't known: for each misapplied name, which sense the Sources citing it used. Q. dumosa, with 64 Galls, matters most. Only the curated files and preview's replay log reach the cutover, so the decision belongs in `aliases.csv` (b5bd M6).
