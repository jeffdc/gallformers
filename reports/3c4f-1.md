## How it was built

### Design notes

A decision item, so no code: the work was gathering evidence and recording the outcome.

Approach: an Explore agent surveyed the API on taxogall against main (endpoints unchanged; rank-taxon, alias and trait-value IDs new; places, sources, aliases, undescribed and search change meaning) and the CI api-version-check (fails when a file under controllers/api/ changes and API_VERSION doesn't; any edit to API_VERSION passes it). Jeff pulled production's request log and its 20 rotated archives (2026-10-11 to 11-16); I analysed them locally with jq and deleted every copy afterwards, since they hold visitors' IP addresses.

Finding: real callers exist (a research pipeline, a weekly monitor script, a plant app's knowledge base, a dataset bot), all on the gall and host endpoints, whose IDs are stable but whose meaning changes. Taxonomy endpoints are barely used except by what looks like AI agents from Chinese networks, which also read the HTML pages six times more than the API.

Why v3 + 410 rather than a bump under /api/v2: same-path changes would let callers silently misread data (places [] now means anywhere); a path change makes them fail loudly, and the fix is small because gall and host IDs are unchanged. Disabling the API was rejected: it breaks honest users and doesn't stop the agents, who also read the pages.

PII: contact details and user agents are only in Jeff's local, gitignored docs/plans/2026-11-16-api-users.md; mull holds descriptions by kind.

New public functions, components, modules: none. Deleted: nothing (6b17 deletes the v2 routes). Unverified: callers that run less than monthly would fall outside the five-week window.

Captured along the way: bugs 4745 (smoke test's ignored family_id parameter), f71d (production /api/v2/genera 500s), 56b4 (CODING_STANDARDS.md log examples use the wrong keys).
