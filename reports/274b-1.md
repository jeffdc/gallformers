The shape, and why:
- Two halves joined by the shared private bucket. Production (main) collects and converts documents, because the work page goes on today's site so other curators can help now. Preview (taxogall) runs the reading, because review decisions must be made there.
- One folder per Source (sources/<id>/), because a layout keyed by digest and run scattered a Source's artifacts (Jeff). Source IDs are stable: existing Sources keep theirs through the migration, and Sources new on preview start at 100000 so the replay can keep the number.
- Stages that write once, done when result.json exists, so a failure never reruns earlier stages and a long Sprite run survives a deploy.
- Signed URLs for every write (browsers, the Sprite, local producers), so no AWS keys leave the app and the app decides exactly which keys each writer may touch. Personal API tokens for the local producer.
- LLM runs on curators' own subscriptions, locally (Jeff: an API key would price Gallformers out, and if subscriptions can't do it the project halts). Hosted runners for the LLM stages were weighed and set aside: Anthropic's terms forbid developers storing or intermediating Claude.ai credentials, and the local route is documented as fine.
- Conversion on a Sprite, because the app machines (1 GB) can't hold a conversion (2 to 6.5 GB measured).

Rejected: S3 paths keyed by digest and run ID (scattered); per-curator IAM users or temporary AWS credentials (static keys on laptops, or more moving parts); copying a run into a package folder (one copy is enough); claims for document collection (unneeded); an automatic identity check by an LLM (a human must verify); running the converter in the app machine (memory).
