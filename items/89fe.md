**The finding** (`294c`, "First golden run", 2026-10-27). Ashmead's Source describes *Andricus imbrecariae* as a "new species". The batch marked the Gall `new`, and the dry run then stopped looking for an existing entry. Gallformers has it as *Kokkocynips imbricariae*. Recorded as an importer question for `e381`: an old Source's "new species" may long exist under another name; intake should still look for the entry. It was one of the 14 "right but now missing" golden items (a name match). `294c` "Open" repeats it: "Importer (`e381`): an old Source's 'new species' still needs matching to an existing entry."

**Is it fixed?** Mostly, as far as the code goes (read 2026-11-11 at a0434bcf). Unverified on the Ashmead package itself.
- **Names** (`Gallformers.Import.Resolver`):
  - The name lookups run before `new` is considered. A taxon the Source calls new becomes `:new` only when nothing matches: no exact name or synonym, no abbreviation, no `name_reading`, no fused oak-gall epithet.
  - Even then, rule G (`Gallformers.Import.NameSuggestions`, since `7a701a71`, 2026-11-04) asks the tree for the name in other spellings, endings or genera, including "the epithet alone, in any spelling, within the family of the genus as written". A hit makes it `:ambiguous`, with the taxa as candidates for a curator, "so … an old Source's name is not created again".
  - Rule C (original combination) and rule H (a held-valid name the Source describes as new, in a gall batch: the tree's taxon is proposed) cover a "new" name that the tree holds as a synonym.
- **This case.** On `gallformers_taxogall`, "Andricus imbrecariae" is held as a synonym of *Kokkocynips imbricariae* (taxon 87275, beside "Dryocosmpus imbricariae"). So the exact lookup finds it. If the taxonomy batch holds it valid (a `name` act), rule H proposes the tree's taxon for a curator instead of creating it.
  - Without that synonym, rule G's variants would not bridge "imbrecariae" and "imbricariae": an internal e/i change isn't among `NameVariants`' spellings (ii/i, æ, œ). Only Host suggestions use edit distance.
- **Galls** (`Gallformers.Import.GallMatcher`): a Gall whose Inducer resolved at species rank is matched against that Inducer's Galls first. `new` only decides the outcome when no candidate is left ("none is `:new` when the Source presents the Gall as new, otherwise `:unresolved`"). So the Gall-level short-circuit the finding describes is gone.
  - There is no test for "a Gall marked new whose Inducer already has a matching Gall still matches it". The tests cover `new` only with no candidates (`gall_matcher_test.exs`, "an Inducer with no Galls: new when the Source says so").

**What's left to settle:**
1. Re-run the Ashmead package (98) dry run and check that *Andricus imbrecariae* reaches *Kokkocynips imbricariae* (resolved, or proposed to a curator) and its Gall matches the existing entry.
2. Add the missing GallMatcher test.
3. Decide with Jeff whether a "new" name whose tree form differs by an internal spelling change and no synonym links them, needs more than rule G. If not, close this.
