Replace `multi_select_dropdown` (FormComponents) with `typeahead`, then delete `multi_select_dropdown`. This is an approved consolidation in the design-system catalog (`docs/design-system/components.md`): `typeahead` is "Approved (consolidate)" and replaces `typeahead`, `multi_select`, `multi_select_dropdown` and `multi_select_typeahead`. The catalog describes it as "Find and pick by name: one component for single and multiple selection (`multiple`), with chips for chosen items, grouped results (accepted name, synonym, WCVP), and keyboard support." bc0d's 2026-11-06 handoff lists `multi_select_dropdown` (→ `typeahead`) among the legacy components still in use.

## Where it is (as of a0434bcf)

- **Definition:** `multi_select_dropdown/1` in `lib/gallformers_web/components/form_components.ex`, with its private helpers `compute_available_options/8`, `get_item_id/2` and `get_display_label/2` (only it calls them). Its CSS classes are `.gf-multi-select-container(-md)`, `.gf-multi-select-input(-md)`, `.gf-multi-select-dropdown(-md)` and `.gf-multi-select-option`, in `assets/css/system/components.css`. `multi_select_typeahead` doesn't use them; check nothing else does before deleting them.
- **One caller:** the article Tags field in `lib/gallformers_web/live/admin/article_live/form.ex` (`id="article-tags"`, static `options` from `Articles.list_all_tags/0`). Its events are `tag_search`, `open_tag_dropdown`, `close_tag_dropdown` (adds the typed text as a new tag when it isn't empty and isn't already chosen), `add_tag` and `remove_tag`. Its assigns are `all_tags`, `form_tags`, `tag_search_query` and `tag_dropdown_open`. A tag change marks the form dirty. The hint reads "Choose a tag, or type a new one and press Enter."
- **`typeahead` has no `multiple` mode today.** It is single-select only: attrs `search_event`, `select_event`, `clear_event`, `query`, `results`, `selected`, `display_fn`, `group_key`, `target`, `allow_new` + `create_event`. So this work adds the multiple-selection mode the catalog entry describes, covering what the tags field needs. If that doesn't fit one session, `mull ask` to split it.
- **No tests cover the Tags field.** `test/gallformers_web/live/admin/article_live/` has none. Write them first, against today's behaviour, and watch them pass. Then swap the component.

## Behaviour that must not change

Jeff, 2026-11-05: "Typeahead behavior must not change. Look and feel may improve, but the exact mechanics are hard-won and must be reused or replicated." The design-system README rule: a replacement starts from its inventory; behaviour changes need Jeff's approval and are recorded under "Approved changes"; prefer new markup around unchanged logic.

The contract is `docs/design-system/inventory/typeahead-and-id.md`, §1 (the shared Typeahead hook), §1c (`multi_select_dropdown`), "Hard-won lessons" and "Behaviors a redesign must preserve". For this component:
- **Two modes.** Static mode (`options`) filters on the server with `TextMatch.matches_all_terms?` over the label and leaves out what is already selected. Async mode (`search_results`) is unused by the tags field.
- **Opening and closing.** The list opens on a click on the container and on input focus. It closes on blur, on click-away, and on Enter with text and no highlight.
- **The close event.** The root sets `data-search-type`, `data-query` and `data-close-event`. For tags, closing with text **adds it as a new tag**. Enter with no highlight and non-blank text pushes `data-close-event` and empties the input. Only `multi_select_dropdown` sets `data-close-event` (hook `assets/js/hooks/typeahead.js`, the Enter branch). The new mode needs it, or that hook branch becomes dead and must go.
- **Mousedown guards.** The dropdown and each chip × use `onmousedown="event.preventDefault()"`, so blur doesn't beat the click.
- **The shared hook.** Search on every `input` event, with payload `{value, type}`. Arrow keys clamp (no wrap), and ArrowUp from no highlight highlights the first option. Enter on a highlight clicks it. Escape only clears the highlight. The highlight is kept across patches. The input is emptied only when `data-query` is `""`, so the first typed character is never erased.
- **No ARIA roles today.** Any change in roles or attributes is a behaviour change to record (the single `typeahead` has `role=combobox`/`listbox`/`option`).
