**What:** a small keyboard for the one-at-a-time review: a `ReviewKeys` hook on the question card (`review_card`, drawn by `GallformersWeb.Admin.ReviewLive.QuestionCard` in `ReviewLive.Review`). **Enter** takes the suggested answer, **S** skips ("Skip for now"), and **up and down** move between the answers. It's inert while the curator is typing in a field. This is 6611's Task 9 (the review rebuild), the one build task it had left. It comes after b230's Tasks 5 and 6 (items a81c and f926), so the card is settled: those retire the step pages and `ItemRow` and move every page onto this card.

**Decided (Jeff, 2026-11-08, the build decisions):** "Keyboard, a small set: Enter takes the suggested answer, S skips, up/down move between answers." The catalog's `review_card` entry (`docs/design-system/components.md`) already says this. It's the one part of that entry not built yet; item 7158's doc-drift fix notes it.

**How the card works today** (6611's build): answers are `review_option`s with `use`, so one click decides. An option that needs input says "Search…" (for a name) or "Choose…" (for a value) and opens its input first. The recommended answer is primary and marked "Suggested" (firm) or "Best guess" (weak). The footer has Add a note…, Read the Source and Skip for now. After a decision the page moves to the next unit, and the next card says "Saved: … Undo". So:
- **Enter** does what clicking the Suggested / Best guess answer's "Use this" does. When there is none, it does nothing.
- **S** does what "Skip for now" does.
- **Up / down** move the focus (or selection) between the answers.
- **Inert while typing:** no key acts while focus is in an input, textarea, select or contenteditable, as in a search's typeahead, the note box, or an answer's opened input.

**Check before building.**
- `assets/js/search_shortcut.js` (as of `a0434bcf`) opens the command palette on `/` and `s` from anywhere on a page with the palette, admin included (`PaletteLive` is on every page), whenever the user isn't typing in a field. The review's S would collide with it.
- The typeahead hook (`assets/js/hooks/typeahead.js`) already handles Escape and arrows inside its field.

Settle how S and the palette's `s` coexist before writing the hook. If it isn't obvious, `mull ask` Jeff. `search_shortcut.js`'s `TYPING` selector and its modifier check are the existing "not while typing" rule, so reuse them rather than writing another.

**Build:**
- The hook in `assets/js/hooks/`, registered in `assets/js/app.js` like the others, with a `.test.js` beside it. Every hook there has one, and the JS tests run in CI.
- It sends the card's existing events. No new decision path: deciding still goes through `ReviewLive.Answer`, the only web caller of `Import.decide_queue_item/3` that `.credo.exs` allows.
- Add any server event it needs to `QuestionCard`/`Review`.
