**What:** in the back end, one decision shape for a name we don't hold (or can't place), and one carry-out, run inside `Import.decide_queue_item/3`'s transaction. Whatever the decision creates (from WCVP, from iNaturalist, by hand) is created when the curator decides and logged with the decision, so Undo takes it back, a refused decision leaves nothing behind, and replay reproduces it. This is the back half of "one way to handle a name we don't have". The other half of b230's Task 2 is item 7378 (one spelling helper, one duplicate check, `Rank.parse/1`). After this, item e7ef builds the one search and item bceb the one answer list on top of this shape.

**Why (finding A, "one name, many paths").** References are as of `65531d59`. `TaxonomyAdmin` is `Gallformers.Import.TaxonomyAdmin`, `lib/gallformers/import/taxonomy_admin.ex` (the audit gave its path as `lib/gallformers/taxonomy_admin.ex`). Today a taxon is created five ways:
1. Host: a link out to the New Taxon page (`QuestionCard` 376-386, `ItemRow` 428, `ReviewComponents` 644; prefill from `Loader.new_plant`/`plant_genus`, loader.ex about 1154/1189).
2. Non-Host: an in-place `{:parent, rank}` picker; the taxon is created at **apply** time by `ApplyTaxonomy.create_new_taxon/3` (apply_taxonomy.ex about 222) and a copy in `ApplyGall` (`create_taxon/3`, apply_gall.ex about 242), origin `:curated`.
3. Synonym split: at decide time, editorial even outside Plantae (`Import.SynonymDecisions`).
4. The New Taxon page (`TaxonomyAdmin.create_taxon/4`).
5. The iNat panel: imports before and outside the decision (`InatTaxa`, inat_taxa.ex about 382), so a refused decision leaves the taxon behind.

The back end also refuses `new` for `:unresolved_host` ("A Host is never created by import (plants come from POWO)", `Import.Queue` about 227-230) but accepts it for an ambiguous Host (about 232), which the UI never offers.

**Jeff's decisions this rests on (2026-11-09):**
- **(1) A plant added by hand at species rank or below needs its Host range**, asked for in place, as the New Taxon page does. The back end requires it.
- **(2) A new non-plant taxon is created when the curator decides**, credited to the Source under review, not later at apply time.
- **(6) The iNat panel in the review hands its choice back to the card.** Its Add no longer imports at once: the chosen taxon, with its ticks, becomes the answer, and the import runs inside the decision. So a refused decision leaves nothing and Undo takes the import back. This settles cb28's open question 13: today the review's "Saved: … Undo" reopens the question and takes back the Source's spelling the decision added, but the taxa, names and links the panel brought in stay, as a separate logged change. On the New Taxon page the panel still imports at once.

**Build:**
- **One decision shape** for a name: `{taxon_id}` | `{wcvp_id}` | `{inat: %{id, ticks…}}` | `{new: %{name, rank, parent_id, range?}}` | `{skip}`, plus `sensu` for a reading. Today's shapes are in `Import.Queue`'s moduledoc table (e.g. `%{"taxon_id" => id}`, `%{"taxon_id" => id, "add_synonym" => true}`, `%{"wcvp_id" => id}`, `%{"new" => true, "parent_id" => id}`, `%{"skip" => true}`); update the table with the change.
  - `Queue.choices` accepts it for `:unresolved_host`, an ambiguous Host, `:unresolved_name` and the `:ambiguous_match` kinds. Remove "A Host is never created by import" (Queue about 227-230).
- **One carry-out**, run inside `decide_queue_item`'s transaction, branching on kingdom:
  - A plant goes through `TaxonomyAdmin.create_taxon/4`, `TaxonomyAdmin.add_plant_from_wcvp/3` or `InatTaxa.carry_out/3`, editorially (plants are edited directly, following WCVP, with no statements), with the Host range required at species rank or below.
  - Any other taxon becomes a statement of the Source under review (made at decide time, decision 2), or of the day's iNaturalist Source ("iNaturalist, accessed <date>", `Sources.inaturalist_source/1`) for an iNat import. For an iNat import that means `InatTaxa.carry_out/3` (actor, plan, the curator's choices; `{:ok, %{taxon_id, added, moved}}`, all or nothing) runs inside the decision: non-plants through `Import.TaxonomyStatements.record/3`, plants through `TaxonomyAdmin.create_taxon/4`, `record_taxonomy_edit/2` and `record_synonym_added/4` with origin `:inaturalist`.
  - What it creates is logged in the decision's `carried_out` entry, so `Undo.reversal/1` (`lib/gallformers/import/undo.ex`) takes it back. Check that `Undo` reverses each kind of creation, and extend it where it doesn't. The synonym split already logs its moves this way (`Import.SplitQuestions`, `"carried_out"`).
  - `ApplyTaxonomy.create_new_taxon` and `ApplyGall`'s copy then only read the decision: nothing is created at apply time.
  - The synonym split (`SynonymDecisions`) creates a non-plant species as a statement too, not editorially.
- **Settings, not separate paths.** These are real differences, kept as settings:
  - Plants are editorial; other taxa are Source statements (the Source under review, the day's iNaturalist Source, or the basis picked on the New Taxon page).
  - WCVP is for plants only.
  - A common-name Host never becomes a synonym and may resolve to a genus or section.
  - A Host reading records the Source's sense of the name (sensu).
  - A Host above species rank goes in as `host_taxon_id`, with no reading.
- **Guardrails** (`.credo.exs`, `SingleEntryPoint`): `Taxa.create_taxon/2` may be called only from `Gallformers.Import`, `Import.ApplyTaxonomy` and `CatalogMigration.Taxa`. Its pending list is empty, so the carry-out creates through the existing owners and never adds a direct call. In `lib/gallformers_web/`, `Import.decide_queue_item/3` and `decide_group/3` are called only from `ReviewLive.Answer`.

**Calls:** `Import.decide_queue_item/3`, `TaxonomyAdmin.create_taxon/4`, `TaxonomyAdmin.add_plant_from_wcvp/3`, `InatTaxa.carry_out/3`, `Import.TaxonomyStatements.record/3`, `Import.record_synonym_added/4`, `Undo.reversal/1`, `Gallformers.Import.Replay`.
**Deletes:** the apply-time creation in `ApplyTaxonomy.create_new_taxon` and `ApplyGall`'s `create_taxon`. They only read the decision afterwards.

**Tests (first, watched failing):** every decision shape on every kind (`:unresolved_host`, an ambiguous Host, `:unresolved_name`, `:ambiguous_match`, the synonym split), including a refused decision leaving nothing behind and Undo removing what each one created. Replay (`Import.Replay`) logs and replays the new shapes.

**Done when:** every name decision creates what it needs at decide time, inside the decision, logged in `carried_out`. Nothing about a name is created at apply time. Undo and replay work for each shape. `mix precommit` is clean, and the duplicate-code baseline is lowered (never raised) if findings dropped.
