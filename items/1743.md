**The gate** (carried from the old ingestion plan into `e381`, "Decisions"). Before production, verify:
- the private bucket blocks public access;
- the application's credentials can read, write, list and delete in it privately;
- incomplete multipart uploads expire after seven days;
- only approved public outputs reach the public bucket;
- the public database snapshot (`db-snapshot.yml`) excludes the new private tables (`b5bd` M3: stored Source text, import packages, disputes, the admin queue).

Sources' documents and text are stored privately; text is shown publicly only where the license allows.

**What the repo already has** (as of a0434bcf; this is configuration and tests, not a check of the live AWS account):
- `infra/s3.tf`, bucket `gallformers-private`: an `aws_s3_bucket_public_access_block` with all four blocks `true`, and a lifecycle rule `expire-incomplete-multipart-uploads` (`abort_incomplete_multipart_upload`, `days_after_initiation = 7`). Its comment still says the bucket is "planned: import batches", and that `source-ingestions/*` holds artifacts of the retired system. Today it holds import packages under `import/<key>/` and the exported replay log under `replay/`, shared by preview and production.
- `infra/iam.tf`, policy `GallformersImageUpload`: `s3:GetObject`, `s3:Put*`, `s3:DeleteObject` on `gallformers-private/*`, and `s3:ListBucket` on the bucket.
- The public snapshot: `priv/snapshot/tables.txt` classifies every table as public, private or private-schema. The workflow refuses to publish an unclassified table, and `test/gallformers/public_snapshot_test.exs` fails while a table is missing from the list. Private there today: `carbonite_default` (schema), `source_documents`, `document_items`, `import_packages`, `import_batches`, `batch_statements`, `batch_unmapped`, `queue_items`, `queue_item_notes`, `package_statement_edits`, `source_corrections`, `oban_jobs`, `oban_peers`, `users` and the analytics tables, among others. `replay_log` is private too (`9449` Task 17). `pending_trait_terms` is listed as public, though it holds package and queue IDs; a separate capture in phase c887 (d641) covers checking it.

**What remains:** run the checks against the real account (is the tofu state applied, can production's credentials do each operation, and is public access refused?), and confirm a real snapshot run publishes none of the private tables. Record the result where the cutover checklist (`b5bd` M6) can see it.
