**What (b5bd M7, "After release"):** "Drop the old tables (the `species`-centric model) once stable." Legacy code is removed on taxogall as each piece is replaced, so little should remain by then.

**The old tables** (`9449` §1, "Replaced (read by the data migration, dropped after release)"):
- `species`, `gall_traits`, `alias`, `alias_species`, `taxonomy`, `taxonomy_alias`, `species_taxonomy`, `gallhost`, `species_source`, `gall_range`;
- the nine `gall_*` Trait joins and the nine Trait vocabulary tables.

The tables that stay are listed there too: unchanged ones (`users`, `place`, `place_hierarchy`, `wcvp_*`, `articles`, `glossary`, `content_images`, `abundance`, `site_settings`, analytics), re-keyed ones (`host_range`, `host_traits`, `image`, `keys`), and `source`, extended in place.

**The `species_id` columns** (`9449`, changes made while building: "`host_range` and `image` gained typed `taxon_id` / `gall_id` columns beside `species_id`; drop `species_id` when the old code goes"):
- `host_range`: `priv/repo/migrations/20261027160000_key_host_range_by_taxon.exs` made `species_id` nullable. The table is unique on `(species_id, place_id)` where that is set and on `(taxon_id, place_id)`, and a row needs one of the two. Its moduledoc: "When today's code goes, `species_id` is dropped and `(taxon_id, place_id)` becomes the primary key." Some rows kept only their species key: where two genus placeholders of one genus gave the genus the same place, one row kept the genus key and the others kept only their species key. Check those rows before dropping the column.
- `image`: `Gallformers.Images.Image` says `species_id` "is the old-model key of the migrated rows, no longer written". Each image belongs to exactly one Gall (`gall_id`) or taxon (`taxon_id`).
- Schemas to update: `Gallformers.Ranges.HostRange` (field, optional fields, the `species_id` unique constraint and the "or species_id is required" check) and `Gallformers.Images.Image`.

**Order and readers.** As of a0434bcf, the old tables are read by:
- the catalog data migration (`Gallformers.CatalogMigration`, through `CatalogMigration.Old`);
- the old ID filter `Gallformers.Galls.Identification`, kept for `mix gallformers.catalog.id_parity` (deleted at cutover, item 42fd). `HostRange`'s `species_id` is "read by the old ID filter until the cutover".

So: release, let it run stable, delete the parity task and old filter (42fd), then drop the tables and columns in one migration. The matters don't say whether `CatalogMigration` is deleted with the tables. It can't run without them, so ask Jeff when this is picked up. Find any remaining reader with `mix xref` and a grep for each table name.

**Related after-release work in the same matter** (separate records): replace `docs/domain/general.md` and `admin-domain-reference.md`; update `CLAUDE.md`, admin onboarding, and runbooks that assume the old tables (e.g. `restore-deleted-gall.md`).
