**What:** three helpers that exist several times over become one each: the Source's spelling as a synonym, the "do we already hold this plant/taxon" check, and `Rank.parse/1`. This is the second half of b230's Task 2 (the back end for a name we don't have). The decision shape and the carry-out are item 11dc. References are as of `65531d59`; go by function names (`loader.ex` lines after about 1152 have moved by -2 since).

**Jeff's decision 3 (2026-11-09):** the Source's spelling becomes a synonym for **every** name, Host or not. A common-name Host still never does: a common name ("the black oak") isn't a scientific name. An earlier idea to exempt OCR errors is dropped. So the next Source that spells a name the same way resolves on its own.

**1. One spelling helper.** It goes in a new `Import.Spelling` or in `Import.HostDecisions`: decide while building, and say which in the hand-back. It does three things: the Source's spelling with its abbreviation expanded; "already holds it"; and `Import.record_synonym_added/4` with an optional sensu.
- **It replaces three copies.** All three end in `Import.record_synonym_added`, and they differ:
  - `HostDecisions.spelling`/`add_spelling`/`holds?` (host_decisions.ex about 139-160). The spelling is `name_reading`, else `name_as_written`, whitespace collapsed. An abbreviated genus ("Q. obtusiloba") is written out with **the plant's** genus, which must have that initial, else it's refused ("the Source's abbreviated genus is not the plant's"). "Holds" compares normalized names with **no sensu**.
  - `GallDecisions.written_out`/`ensure_synonym` (gall_decisions.ex about 334-375), used for a Host reading. An abbreviated genus is written out with **the one genus of that initial the batch writes in full**, else left as written. "Holds" compares normalized name **and sensu**, and records the synonym with the reading's sensu.
  - `Loader.expand_genus` (`review_live/loader.ex` about 1178), web side: the prefill for a new plant's name. It expands with the batch's genera when exactly one has that initial.

  The helper has to settle these differences in one rule. Say in the hand-back which rule it keeps, and why.
- **Where it runs:** for every name decision except a common-name Host (decision 3). Today only Host decisions, Host readings and `synonym_of` add a spelling.

**2. One duplicate check** for "do we already hold this plant/taxon", used by the New Taxon page (`TaxonomyLive.New`'s `duplicate_warnings`, new.ex about 526), `HostDecisions.held_plant` (the plant linked to an accepted WCVP record, else the one holding its name at the record's rank, about line 201) and `InatTaxa.held` (by iNat ID, else the name at its rank in its kingdom, `Taxa.resolve_name/2`; inat_taxa.ex about 197).

**3. `Rank.parse/1`** in `Gallformers.Taxa.Rank` (`lib/gallformers/taxa/rank.ex`), replacing the copies of `Enum.find(Rank.all(), &(Atom.to_string(&1) == rank))`. As of `a0434bcf` there's one in each of: `catalog_migration/curated.ex`, `import/gall_decisions.ex`, `import/inat_taxa.ex` (`InatTaxa.our_rank/1`, about line 190), `import/queue.ex`, `admin/review/questions.ex`, `live/admin/inat_taxon_panel.ex` (`InatTaxonPanel.rank_of/1`), `live/admin/review_live/loader.ex`, `live/admin/taxonomy_live/new.ex` and `live/admin/taxonomy_live/taxon_changes.ex`. That's nine. Check `InatTaxa.our_rank/1` too, since it maps iNat's rank strings.

**Calls:** `Import.record_synonym_added/4`, `Taxa.resolve_name/2`, `Gallformers.Taxa.NameNormalizer.normalize/1`, `Rank.all/0`.
**Deletes:** `HostDecisions.spelling`/`add_spelling`/`holds?`, `GallDecisions.written_out`/`ensure_synonym`, `Loader.expand_genus`, the three duplicate checks (whichever two aren't kept), and the nine inline rank lookups.

**Tests (first, watched failing):** the spelling is added for each kind of name decision and never for a common-name Host. A spelling already held isn't added twice. An abbreviated genus is expanded (and refused where it can't be). A Host reading keeps its sensu. Each caller of the duplicate check finds a held plant or taxon. `Rank.parse/1` unit tests, including an unknown rank. Every new synonym is in the replay log.

**Done when:** one spelling helper, one duplicate check and `Rank.parse/1` exist, and every copy above is deleted. `mix precommit` is clean, and the duplicate-code baseline is lowered (never raised) if findings dropped.
