**The gap.** Carbonite (the audit trail, `ede2`; schema `carbonite_default`) records row-level changes on the new tables: `facts`, `attributions`, the detail tables, `galls`, `taxa`, `taxon_names`, the queue, the replay log, and so on. The `source` table is not tracked, and neither is `host_range` (`a856`, "Deviations and notes": "`host_range` and `source` aren't Carbonite-tracked (a range save / Source edit runs in an audit transaction naming the actor, and its replay-log entry holds the change; tracking `source` is a follow-up)").

As of a0434bcf, only `source_documents` and `source_corrections` on the Source side have triggers (`Gallformers.Audit.Migration.track_table/2`, called in `20261024230100_create_source_documents.exs` and `20261108100000_create_source_corrections.exs`). The consequence the matters record: **creating a citation is logged as a Source edit**, because there is no row audit on `source` (`f923` Task 8; `50ff` "For Jeff's review", Curation). So the change history can't show a Source row's own before and after.

**What to do.** Add a migration that tracks `source` with the helper the other tables' migrations use: `Gallformers.Audit.Migration.track_table("source")` in `up`, and `untrack_table` in `down`. Updates then keep the values they replaced (`store_changed_from`). Then check:
- that every write to `source` already runs inside `Audit.transaction/3` (an audited write without metadata is rejected, and there is no default actor);
- whether the citation-as-Source-edit logging can then become a plain audited insert;
- that `carbonite_default` stays out of the public snapshot (it is a `private-schema` in `priv/snapshot/tables.txt`).

`a856` names only `source` as the follow-up. Whether `host_range` should be tracked too is not decided.
