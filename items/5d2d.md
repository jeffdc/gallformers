Matter 8567 (the taxonomy and gall systems design) is still cited as the design reference, but two of its rules no longer match the code or the later edit-model decisions (d3b0). Anyone reading 8567 to learn how edits work is misled. The fix is to the docs and references, not the code: mark rules 11 and 12 superseded by the unified edit model, wherever the design is restated (e.g. the plan doc and any repo doc that cites 8567 for how imports and edits work).

**Rule 11, as written:** "Import follows `e381`. Facts from a Source aren't curated after import; a curator who disagrees adds a **Gallformers** statement (confirming or denying). Re-import replaces a Source's attributions."

**Rule 12, as written:** "Pipeline artifacts are the primary admin interface (Jeff, 2026-10-05). Data gets in and gets fixed through trusted pipeline batches, not hand-edited forms; screens exist only where unavoidable: taxonomy, batch approve/deny (with unresolved references), and retraction. Curator corrections can follow the same path: a curator writes plain notes, an LLM turns them into a batch attributed to the Gallformers Source, and it is validated and approved like any other. … Restated 2026-10-06: every write is a batch: the interface is the import JSON Schema (or a fragment of it), so any tool, screen, human, or LLM that produces valid JSON can deliver updates."

**What replaced them (d3b0, Jeff 2026-11-07):**
- New Facts come in exactly two ways: ingest a Source to approval, or edit or add a Fact on a Fact-bearing entity.
- An edit is the ingestion of a Gallformers statement, through the same code path as a Source ingestion.
- Correcting an ingestion mistake (fixing a misreading) is done under the original Source's authority, not as a Gallformers statement. That contradicts rule 11's "a curator who disagrees adds a Gallformers statement".
- All edits that can be inline are inline on the main pages, through Edit mode, the tray and the Fact inspector. That contradicts rule 12's "screens only where unavoidable".

**Where the code writes Facts outside the ingestion path** (d3b0's audit of 2026-11-07; each function checked present at a0434bcf). Only the Gall page's tray Fact items use the ingestion path: Hosts, Traits, common names, range exclusions and observation intake (`Curation` → `Import.submit_gallformers_fragment/2`). These write Facts directly:
- taxonomy edits: `Import.TaxonomyStatements`, via `BasisPicker`;
- Source corrections: `Import.SourceCorrections`;
- merge and rename aliases: the private `add_former_label` in `Catalog.Records`, and `Catalog.GallRenames`;
- split answers: `Catalog.repoint_inducer/4` (delegates to `Records.move_gall_inducer`);
- vocabulary term moves: `Catalog.move_term_attributions`;
- Trait-term placements outside apply.

Moving these onto the one path is the edit model's back-end work. This capture is only about the design reference saying otherwise.
