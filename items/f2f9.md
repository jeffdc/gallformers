Batch the largest query classes in the Fact writer and the resolver, measured against the large test package and the baseline profile from the previous item (b408).

## Decided

Jeff chose **route A** (2026-11-08): batch the per-Fact and per-name queries in the Fact writer and the resolver. Why: it is general, it also speeds up approval (which runs the same apply), and it may give 3–5×. The other route, (B) re-resolving and re-previewing only the Galls a decision touches, is riskier: a taxon or Trait-term decision touches many Galls, and a partial recompute must match a full one. B is decided only after A is measured on the large package.

## What to batch

From the 2026-11-08 counts; re-rank them with b408's profile before starting:

- Carbonite transaction inserts (~534 per dry run);
- locks;
- per-Fact attribution and evidence inserts;
- Source lookups (~163 per dry run);
- `trait_term_mappings` lookups;
- in the resolver: the taxon name, common name and ancestry lookups made per name (~16 ms per Gall on a decision's re-resolve).

The dry run costs ~3.5 ms per Fact written (~25 small queries per Fact: attributions, evidence, names, Carbonite transaction rows, locks). For ~570 Galls (Gagné 1989) that is a 15–20 s dry run and a ~9 s wait on every decision.

**The pattern that already worked** (the slot fix, `14c19024`, on taxogall): `Facts.with_slot_siblings/1` used `id IN … OR slot IN (subquery)`, a full scan of `facts` on every Fact written (2.5 ms × 362 per dry run). Reading the slots first and passing them as a list let both conditions use their index; it took package 118's dry run from 1.8 s to 0.7 s and also sped up approval. Look for the same shape: a lookup or insert made once per Fact or per name that can be made once per batch.

**Where the code is** (as of a0434bcf): the dry run, `Import.preview_package/2`, applies each pending batch through the batch's runner (`Gallformers.Import.ApplyGall.run/1`, `run_facts/3` for gall batches) inside `Audit.transaction`, rolled back; approval runs the same apply for real. Names: `Gallformers.Import.Resolver`, through `Taxa.resolve_name/2`.

## Constraints

- The dry run and approval must write exactly what they wrote before: the existing import, preview and apply tests stay green unchanged. Add a test first for any batched path whose behaviour could differ (for example a lookup that used to see a row written earlier in the same batch).
- Every Fact edit stays audited and replay-logged as before; batching Carbonite rows must not lose a change from the audit.
- Profile on `gallformers_c90c` (127.0.0.1:54317), never the shared dev databases.

The hand-back gives before and after for both, so Jeff can decide whether route B is still needed. When the measuring is finished, `gallformers_c90c` is to be dropped: ask Jeff before dropping it.
