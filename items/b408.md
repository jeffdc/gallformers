Build a large import test package from the five v6 Sources combined, then profile one dry run and one decision on it. This is the measuring step of route A (Jeff, 2026-11-08: batch the per-Fact and per-name queries in the Fact writer and the resolver); the batching itself is the next item, and is measured against what this one records.

## Why

`Import.preview_package/2` is the dry run behind the review's reading of a Source: it applies every pending batch in a transaction that is rolled back, and it is recomputed after every decision. Measured on 2026-11-08 on a copy of `gallformers_taxogall`:

| Package | Dry run before | Dry run after the slot fix | A decision (re-resolve) |
|---|---|---|---|
| 118, 21 Galls, gall batch writes ~200 Facts | 1.8 s | 0.7 s | 0.34 s (resolve) |
| 116, 39 Galls, gall batch held | 1.2 s | 0.9 s | 0.65 s |

The dry run costs ~3.5 ms per Fact written (~25 small queries per Fact: attributions, evidence, names, Carbonite transaction rows, locks). A decision costs ~16 ms per Gall to re-resolve the package (taxon name, common name and ancestry lookups per name). For a Source of ~570 Galls (Gagné 1989) that is roughly a 15–20 s dry run in the background and a ~9 s wait on every decision. The small packages above can't show where the time goes at that size, hence a large package.

## What to build

- **The package:** the five trial Sources from the v6 run, combined into one package: `services/import-producer/output/v6-2026-11-07/` (local and gitignored): `21-corrections-1862`, `502-floate-2010`, `680-nastasi-davis-2022`, `729-aphis-rubifolii`, `98-ashmead-1896`, each with its `taxonomy.json`, `gall.json` and `review.json`. Dev keeps packages on local disk (`Storage.Private.LocalAdapter`), and `Import.register_package/3` (actor, key, attrs), `Import.validate_package/3` and `Import.resolve_package/2` take one through (arities as of a0434bcf). Keep the build repeatable (a script or mix task under `dev/` or the test support), so the next item can rebuild and re-measure the same package.
- **Where to profile:** `gallformers_c90c` on 127.0.0.1:54317, a fully migrated copy of `gallformers_taxogall` kept for this work. Never the shared dev databases.
- **What to profile:** one dry run (`Import.preview_package/2` on the package) and one decision (the re-resolve that follows it).
  - Count queries per table with a telemetry handler on the Repo's query events (`[:gallformers, :repo, :query]`; `Gallformers.Repo` uses Ecto's default prefix).
  - Time with `:tprof`; it needs `Mix.ensure_application!(:tools)` first.
- **What to look at first** (the largest classes in the 2026-11-08 counts): Carbonite transaction inserts (~534 per dry run), locks, per-Fact attribution and evidence inserts, Source lookups (~163), `trait_term_mappings` lookups. Where they come from, as of a0434bcf: the dry run applies each pending batch through `Import`'s private `preview_batch/5` and the batch's runner (`Gallformers.Import.ApplyGall.run/1`, `run_facts/3` for gall batches) inside `Audit.transaction` (that is where the Carbonite rows come from), collected by `Gallformers.Import.Preview`; names go through `Gallformers.Import.Resolver`, which looks each one up with `Taxa.resolve_name/2`.

## Done when

The package builds and goes through validate, resolve and the dry run on `gallformers_c90c`, and the hand-back records, for one dry run and one decision: the total time, the query count per table (largest first), and the `:tprof` hot spots, so the batching item has its baseline and its targets.

The function profiled is the same either way the open ordering question goes: as of a0434bcf both the review's `dry_run/2` (`ReviewLive.Review`) and the Facts page's `load_facts/2` (`ReviewLive.Facts`) call `Import.preview_package/2` per package. b230 Task 5 (item a81c) replaces the first with the second (several packages merged, errors handled).
