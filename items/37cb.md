**Why.** Preview (`gallformers-preview`, gallformers-preview.fly.dev) is no longer a throwaway deploy. It is the persistent staging server where Sources are processed into a copy of production (step 5) and the cutover is rehearsed (step 6). Curators' decisions made there carry to production through preview's replay log, and no other way. The files that describe and build preview still describe the old role (a disposable instance, and earlier a baked-in SQLite database). The phase doc (f709) says what preview must be.

**What is stale.** Checked 2026-11-11 against a0434bcf. Fix each, or confirm it is intended and say why in the file.

`fly.preview.toml`
- The header reads "Disposable preview instance with baked-in database (no volumes)". Yet the file mounts a volume (`[mounts] source = "gallformers_preview_data", destination = "/data"`), and the database is Fly Postgres reached through `DATABASE_URL`. Neither half of the header is true now.
- Nothing on preview uses `/data`. `config/runtime.exs` skips the `/data/logs` file logger when `PREVIEW_DEPLOY` is set, and `docker-entrypoint-preview.sh` never touches `/data`. `Dockerfile.preview` also creates no `/data` and runs as `USER gallformers` with no chown. The production `Dockerfile` creates `/data` and chowns it, and `docker-entrypoint.sh` chowns it again. Decide whether preview keeps the volume. If it does, make it usable; if not, remove the mount.
- `TILES_URL` is not set in `[env]`. `Dockerfile.preview`'s comment and `runbooks/map-tiles.md` both say preview must set it to `https://gallformers.org/tiles/boundaries.pmtiles`; without it, `runtime.exs` falls back to `/tiles/boundaries.pmtiles`. It may be set as a Fly secret (unverified: the secrets aren't visible from the repo).
- Region `iad` (production is `ewr`); health-check grace 120 s (production 30 s). These are not necessarily wrong. `b5bd` M5 wants preview for "production-like timing", and the VM already matches production's (shared, 1 CPU, 1 GB).

`Dockerfile.preview`
- The header reads "WCVP sqlite and boundaries PMTiles baked into image from S3". That is stale. WCVP is a separate Postgres database named `wcvp` on the same cluster (`runbooks/wcvp.md`; `runtime.exs` derives its URL from `DATABASE_URL` by replacing the database name), and tiles come from CloudFront.
- It has drifted from the production `Dockerfile`:
  - no separate Node stage: it runs `npm install` in the builder instead of `npm ci --omit=dev` from the lockfile;
  - no `su-exec`, and no `/data` setup;
  - a different entrypoint.

  Bring the parts that should match back in line with `Dockerfile` (the toolchain line already matches CI: Elixir 1.19.6 / OTP 28.5.0.8 / Alpine 3.24.3). Keep the real differences, such as `PREVIEW_DEPLOY=true` at build, and comment them. CI already builds both files (`.github/workflows/ci.yml` path filters).
- `docker-entrypoint-preview.sh` runs only `Gallformers.Release.migrate()` (the schema migrations) at boot. That is right: the catalog data migration must never run at boot (`b5bd` M0, because Fly health checks and `HealthWatchdog` would restart it mid-run). It runs as its own step: `bin/gallformers eval "Gallformers.Release.migrate_catalog()"`.

The preview runbook
- **There is no preview runbook** (`runbooks/README.md` lists none). What exists is scattered:
  - `runbooks/wcvp.md`, "Preview": the `wcvp` database on the same Fly Postgres cluster, loaded by pg_restore via `fly proxy` from the S3 dump; update step "4. Same for preview if needed".
  - `runbooks/map-tiles.md`, "Preview": `TILES_URL`.
  - `runbooks/postgres-cutover.md`: the table gives preview's database app as `gallformers-preview-db` "(to be provisioned)", with an unchecked "Provision `gallformers-preview-db`".
  - `runbooks/restore-database.md`: lists "Refreshing preview data" as a use.
  - The `Makefile`, "Preview Deploys": "Deploy current branch to a disposable Fly.io preview instance. One-time setup: fly apps create gallformers-preview && fly secrets set ... (mirror prod secrets)"; `make preview`, `preview-stop` and `preview-destroy` (`fly apps destroy gallformers-preview --yes`).
- Write one preview runbook (and add it to the index), or bring each of those up to date. Either way, cover:
  - **What preview is for.** Persistent staging holding curator decisions; it is not disposable. `preview-destroy`, or restoring over preview's database, loses every decision not yet exported. The Makefile comment and target should say so.
  - **Setting it up.** The Fly app; the Postgres app and its two databases (main and `wcvp`); the secrets `runtime.exs` reads: `DATABASE_URL`, `SECRET_KEY_BASE`, `AUTH0_DOMAIN`, `AUTH0_CLIENT_ID`, `AUTH0_CLIENT_SECRET`, `S3_PUT_AWS_ACCESS_KEY_ID` and `S3_PUT_AWS_SECRET_ACCESS_KEY`, and `TILES_URL` if it stays a secret. Plus the env in the toml (`PHX_HOST`, `S3_IMAGE_PREFIX = "preview"`, so uploads go under `preview/` in the images bucket; `PREVIEW_DEPLOY`). `gallformers-preview.fly.dev` is already in `check_origin`.
  - **Loading data.** WCVP from the S3 dump (`mix gallformers.wcvp.restore` defaults to `https://gallformers-backups.s3.amazonaws.com/public/wcvp.dump`), then a production copy (the latest `s3://gallformers-full-backups/<date>/gallformers.dump`, as `make download-db` finds it). Then deploy, and run the catalog migration as a release task: `Gallformers.Release.migrate_catalog()`, strict, which stops with nothing written on any pending curated decision or duplicate taxon key.
  - **The private bucket.** `gallformers-private` is shared by preview and production on purpose (`Gallformers.Import.ReplayExport`). Packages live under `import/<key>/`, and the migration never deletes them, Sources or their stored documents. Preview's AWS credentials must reach it.
  - **At cutover.** On preview, `bin/gallformers eval "Gallformers.Release.export_replay_log()"` writes `replay/replay_log-<UTC time>.json` to the private bucket; keep the key it prints. No preview decisions after this (`b5bd` M6 step 3). Production then runs `Release.migrate_catalog()` and `Release.replay_log("<key>")` (M6 step 7).

**Done when** both files' comments describe what they do now; `fly.preview.toml` and `Dockerfile.preview` differ from the production files only where preview really differs, each difference commented; and one runbook (or the updated set) is enough for someone to set preview up, load it, run the catalog migration on it, and export its replay log, without reading the matters.
